# Rules

The [table of the rules](../README.md#rules) says what each rule checks and what reports it. This page says how they are reported, how to choose which analyzer rules are on, and what each rule cannot see.

## How a rule is reported

- **Analyzer rules** (HS000, HS003 to HS011, HS015, HS016, HS019, HS900 to HS902) come from the `HardSlice.Analyzers` package. They fail `dotnet build`, and show in the IDE as you type. HS019 is a suggestion only: the build output does not show it, the IDE and the compiler log (`ErrorLog`) do.
- **Architecture tests** (HS001, HS012 to HS014, HS016 to HS018) live in `tests/<App>.ArchitectureTests/` of every generated solution. They fail `dotnet test` and the check scripts, not `dotnet build`, and do not depend on the analysis mode.
- HS900 to HS902 report a `hardslice.json` that the analyzers cannot use, or a domain type mapped by EF Core that it does not classify. They are reported only when an active rule depends on the classification of types.

Every message names the offending symbol, the rule in one sentence, the expected fix, the [skill](agent-loop.md#skills) that fixes it and the sheet of the rule:

```text
HS016: 'CancelBookingHandler' in slice 'Bookings/CancelBooking' uses 'ConfirmBookingHandler' from slice 'Bookings/ConfirmBooking'. Slices never reference each other. Fix: move the shared rule into a domain aggregate, raise a domain event, or use the public contract of module 'Bookings'. Skill: extract-to-domain. Doc: 'docs/rules/HS016.md'.
```

Each generated solution carries the sheets in `docs/rules/`, at the path its diagnostics announce, and `dotnet hardslice explain <rule>` prints them. A sheet says what the rule forbids, how to fix a violation, and which workarounds are forbidden.

## Analysis modes

The MSBuild property `HardSliceAnalysisMode` chooses which analyzer rules are on: `Minimum`, `Recommended` (when it is not set) or `All`. A generated solution sets `All` in its `Directory.Build.props`. A mode turns a rule on or off, never changes its severity, and a `dotnet_diagnostic.<rule>.severity` line of `.editorconfig` takes precedence over it, except for HS000. Any other value fails the build with the list of modes.

| Rule | `Minimum` | `Recommended` | `All` |
|---|---|---|---|
| HS000 | error | error | error |
| HS003 | error | error | error |
| HS004 | – | error | error |
| HS005 | – | error | error |
| HS006 | – | error | error |
| HS007 | error | error | error |
| HS008 | – | error | error |
| HS009 | – | error | error |
| HS010 | error | error | error |
| HS011 | error | error | error |
| HS015 | – | error | error |
| HS016 | error | error | error |
| HS019 | – | – | suggestion |
| HS900 to HS902 | error | error | error |

A dash means the mode turns the rule off: `Minimum` keeps the rules that assume neither the shape of a slice, the messaging of the template, its aggregates referenced by identifier nor its domain events declared as records, plus HS016. HS019, a heuristic, is a suggestion of the `All` mode only: it never blocks the build, even with `TreatWarningsAsErrors`. In `Minimum`, HS901 never requires the `command` and `query` contracts. HS000 is not configurable: no mode, `.editorconfig` line or `<NoWarn>` turns it off.

## Known limitations, rule by rule

- `HardSlice.Analyzers` is supported only in a solution generated by `hardslice-api`, whose `docs/rules/` holds the sheets its diagnostics point to. A solution keeps the template it was generated from, and the versions of `HardSlice.Analyzers` and `HardSlice.Tool` it pins.
- HS900, HS004 for a system command that its module never sends, and HS015 for an endpoint its module never maps, are reported at the end of the analysis of a project: the IDE shows them with full solution analysis only.
- **HS000** checks the suppressions written in source only: `<NoWarn>`, `<WarningsNotAsErrors>` and the severities of `.editorconfig` and `.globalconfig` are not detected, since the analysis modes turn rules off through a global config themselves. Review and the CI of the solution protect these files. It checks the form and the length of a justification, never whether the reason is true.
- **HS003** reads the body of the endpoint only: the methods it calls are not followed, and a delegate stored in a variable or declared in another assembly is not analyzed.
- **HS004** checks the slices of the project that declares them, by the namespaces `<Assembly>.Features.<Module>.<Slice>` and the folders below the project directory: the name and the number of the files of a slice are free, and generated code is not checked. A reaction slice is recognized by its domain event handler: whether the handler stays inside the transaction, without external effect, is a review matter. A system command counts as sent when a type of its module creates it or names it as a generic argument: whether that type runs, a hosted service its module registers for example, is not checked. That part of the rule is reported at the end of the analysis of a project.
- **HS005** follows the declared types of the response: an entity typed `object` or `dynamic`, held by a non-public member or reached through the members of a library type is not detected, and a generic handler whose response is an unconstrained type parameter is not analyzed.
- **HS006** analyzes the code of the query handler only, without control flow: a query obtained from a field, a parameter or a helper, a local reassigned other than as `query = query.<operators>`, a compiled query and a write made in a helper or through another library are not analyzed. An `AsNoTracking()` added by a conditional reassignment guarantees nothing, and the global `UseQueryTrackingBehavior` is not read.
- **HS007** checks each entity in the project that declares it, by the accessibility of its accessors and fields: a write by reflection, through a public mutable collection the entity exposes, or by a public method that only assigns its parameter is not detected.
- **HS008** checks each entity in the project that declares it, by the declared types of its properties and fields: a root held through `object`, an unclassified interface, a type parameter or the members of another type is not detected. The owners of a child entity are the roots of the same project that reach its type: a child that no root reaches, or a reference from a child to a root of another project, is not reported, and the rule reads types, not instances.
- **HS009** checks that each domain event is a record, in the project that declares it, not that it is immutable: a record with a public setter is accepted.
- **HS010** checks the domain project, recognized by its entity contract in `hardslice.json`, and the slices only, and reports a `Task.Delay` or a `new PeriodicTimer` without `TimeProvider` in the slices only: the module, `Shared` and `Program.cs` are not checked, and the methods they declare that a slice calls are not followed. `TimeProvider.System` is not reported.
- **HS011** recognizes the blocking members of tasks and their awaiters only: `Thread.Sleep`, `SemaphoreSlim.Wait`, synchronous APIs and the methods the code calls in other assemblies are not followed, and a task never awaited is not reported.
- **HS015** checks the endpoints mapped under `Features` only, and accepts the result types of `Microsoft.AspNetCore.Http.HttpResults` only: a custom `IResult` is reported. The module must call the method of the slice that maps the endpoint, not a helper of it.
- **HS016** is analyzed within one assembly: slices and modules are folders of the web project.
- **HS019** reads the form of the name only: `RoomSeed` passes although it is no past fact, an irregular past participle missing from the list of the sheet is reported, and no exception can be configured. Abstract events and event interfaces are not checked.

## Limitations of the generated application

- PostgreSQL is the only database. SQL Server and Aspire orchestration are planned for v1.0.
- Domain events are published to their handlers inside the transaction of the command, before its commit: no outbox, no publication after commit, no bus and no asynchronous processing. A handler that sends a request through `IMediator` fails at runtime. An external effect in a handler is not detected.
- The generated application has a Development configuration only: no production settings, authentication or deployment.
- CI runs on Linux: `scripts/check.ps1` is verified with PowerShell 7 on Linux, not on Windows.
- The adoption of existing solutions (`dotnet hardslice init`, `map`, `baseline`, `report` and `verify`) is planned for v0.5.

# HS017: Shared stays cross-cutting

Severity: error. Reported by the architecture tests (`tests/MyApp.ArchitectureTests/SharedTests.cs`), which fail `dotnet test` and the check scripts.

## Rule

`src/MyApp/Shared/` holds cross-cutting code only, never a use case or a module's code:

- no type of `MyApp.Shared` uses a type of `MyApp.Features`, including types directly in that root namespace, module contracts and exceptions named only in catch clauses;
- `Shared` contains only the folders listed in `hardslice.json`, by default `Messaging`, `Persistence`, `Behaviors` and `Http`. Subfolders of an allowed folder, such as `Persistence/Migrations`, are allowed.

Each default folder has one role:

| Folder | Holds |
|---|---|
| `Messaging` | The mediator: `IMediator` and its implementation, the contracts of requests, handlers and behaviors, and `AddRecurringCommand`. |
| `Persistence` | `AppDbContext`, its registration and the migrations. |
| `Behaviors` | The mediator pipeline, the `IPipelineBehavior<,>` every request goes through: logs, validation, the transaction of a command and the publication of its domain events. |
| `Http` | The HTTP pipeline, around every endpoint: the answers to unreadable requests and to validation and domain errors, and the authentication schemes, the authorization policies, rate limiting and CORS of the application. |

## How Shared is identified

| Checked | Where |
|---|---|
| Dependencies | Every type whose namespace is `MyApp.Shared` or below, in the compiled assembly, method bodies included. |
| Folders | The namespace of every type of `MyApp.Shared` (`MyApp.Shared.<Folder>`) and every C# file under `src/MyApp/Shared/` on disk. A file directly in `Shared/`, outside any folder, is reported too. |

`hardslice.json`, at the solution root, gives the allowed folders:

```json
{
  "style": "slices",
  "shared": {
    "allowedFolders": ["Messaging", "Persistence", "Behaviors", "Http"]
  }
}
```

A missing or invalid `hardslice.json` (unknown key, style other than `slices`, empty or malformed folder list) fails the architecture tests with a message that starts with `hardslice.json:`.

## Allowed references

- Any type of `MyApp.Shared`.
- The domain project: aggregates, value objects, domain events, `DomainException`.
- Framework and third-party types.

## Diagnostic

```text
HS017: 'ModuleRegistry' in 'Shared/Behaviors' uses 'BookingsModule' in module 'Bookings'. Shared is cross-cutting and never depends on Features. Fix: move the code that needs 'BookingsModule' into module 'Bookings', or declare in Shared an abstraction that the module implements and registers. Skill: fix-architecture-violation. Doc: 'docs/rules/HS017.md'.
HS017: 'TextHelpers' is in 'Shared/Helpers', a folder hardslice.json does not allow. Shared holds only cross-cutting code, in the folders allowed by hardslice.json: Messaging, Persistence, Behaviors, Http. Fix: move a use case into its slice and module-specific code into its module under 'Features'; keep in Shared only cross-cutting code, in an allowed folder. Skill: fix-architecture-violation. Doc: 'docs/rules/HS017.md'.
```

The first symbol is the offending type or file in `Shared`, the second, when there is one, is the type of `Features` it must stop using.

## How to fix

Pick the first option that matches what the code in `Shared` does.

1. **It serves one use case**: move it into that slice, `src/MyApp/Features/<Module>/<Slice>/`.
2. **It serves one module**: move it into the module, directly in `src/MyApp/Features/<Module>/`. The module registers its own services in `<Module>Module.cs` and maps its own aggregates in `<Aggregate>Configuration.cs`.
3. **Shared must call module code** (a registration, a mapping, a handler): invert the dependency. Shared declares an abstraction or discovers implementations in the assembly, and each module implements or registers it. `AppDbContext` applies the configurations it finds in the assembly instead of naming them.

   ```csharp
   // Before, in Shared/Persistence: Shared names a module type.
   modelBuilder.ApplyConfiguration(new RoomConfiguration());

   // After: each module declares its mapping, Shared discovers it.
   modelBuilder.ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly);
   ```

4. **It is truly cross-cutting but fits no allowed folder**: put it in the allowed folder that matches its role, as the table of the rule gives it: `Messaging` for the mediator, `Persistence` for the database, `Behaviors` for the mediator pipeline, `Http` for the HTTP pipeline. An authentication scheme that protects the endpoints of several modules, its options, its policy and the extension that registers them go in `Http`, never in `Behaviors`, which runs inside the mediator, after the endpoint. A new folder requires a maintainer decision.

Then run the check script: it must pass with no HS017.

## Skill

The message names the `fix-architecture-violation` skill, in `.claude/skills/` and `.agents/skills/`: it reads the diagnostic and this sheet, applies the first fix above that matches, runs the check script again, and stops to explain the conflict when only a workaround would make it pass.

## Forbidden workarounds

These mechanisms are not valid fixes for HS017. An exception requires an explicit maintainer decision:

- Editing `hardslice.json` to allow a new folder or to change the style.
- Giving a type of `Shared` a namespace that does not match its folder, or a type of `Features` a namespace under `MyApp.Shared`.
- Reaching `Features` indirectly from `Shared`: reflection on a module type name, `dynamic`, `Type.GetType`, `Activator.CreateInstance`.
- Moving a module's code into the domain only because `Shared` cannot use it.
- Deleting, skipping or editing `SharedTests`, `HardSliceConfiguration` or any other code in `tests/MyApp.ArchitectureTests/`.

# HS004: a slice holds one entry named after it, a request or a domain event handler, in its own folder

Severity: error. Reported at build time by `HardSlice.Analyzers`, in the `Recommended` and `All` analysis modes. Not reported in test projects.

## Rule

A slice is the folder `src/MyApp/Features/<Module>/<Slice>/` and the namespace `MyApp.Features.<Module>.<Slice>`. It has exactly one entry. A request slice holds:

1. exactly one request: the command `<Slice>Command`, which implements `ICommand<TResponse>`, or the query `<Slice>Query`, which implements `IQuery<TResponse>`;
2. its handler, `<Slice>Handler`, which implements `IRequestHandler<TRequest, TResponse>` for that request;
3. its endpoint, the static class `<Slice>Endpoint`, whose `Map(RouteGroupBuilder group)` method its module calls (HS015);
4. the validator of its request, if it has one, named `<Slice>Validator`. Whether a command needs one is HS013's concern.

A system command, such as `CollectFeedsCommand`, is a command that only the application sends, never an HTTP request: a job, or a hosted service that reacts to an outside event. It implements `ISystemCommand<TResponse>`, which derives from `ICommand<TResponse>`, and its slice holds the command, its handler and its validator, if any, but no endpoint. No HTTP mapping sends it, wherever the mapping is declared. A type of its module other than its handler and its validator sends it: that type creates the command, or names it as a generic argument of a method it calls or of a type it derives from, such as `AddRecurringCommand<TCommand, TResponse>` in the module for a periodic or daily task, or a hosted service in the folder of the slice. The contract is the optional key `systemCommand` of `hardslice.json`: without it, every command has an endpoint.

A reaction slice, such as `Features/Bookings/NotifyOnBookingConfirmed/`, reacts to a domain event instead. It holds exactly one domain event handler, `<Slice>Handler`, which implements `IDomainEventHandler<TEvent>` for one event, and neither request nor endpoint: the event triggers it, inside the transaction of the command that raised it.

No request, handler, domain event handler or request validator is declared outside a slice: not at the root of a module, not in `Shared`, not anywhere else in the project.

The folder and the namespace hold the same types: every declaration of a type of the slice is in a file under `Features/<Module>/<Slice>/`, its subfolders included, and every type declared in that folder belongs to the namespace of the slice or a namespace below it. A partial type is checked declaration by declaration.

Requests and handlers are recognized by the contracts of `hardslice.json` (`command`, `systemCommand`, `query`, `requestHandler`, `domainEventHandler`), directly or through a base class; validators by `IValidator<T>` of FluentValidation, for a request `T`. A generic request is named without its arity: `ArchiveBookingCommand<TReason>` is named `ArchiveBookingCommand`. Other types of the slice, such as its DTOs, are free.

## Why

A command that only the application sends needs no endpoint, and one would expose it to anyone: a public route that spends the quota of an external service, or runs a job on demand. A system command that nothing sends is dead code that looks alive.

The slice is the unit an agent reads and changes: its name finds its folder, its folder holds the whole use case, and nothing else is in it. A request named after another use case, a second request that grew into the slice, a handler at the root of the module, a reaction hidden in the slice of a command or a file left in the wrong folder each break that promise silently: the next reader opens the wrong file, or misses the one that matters. The naming also lets the module, the tests (HS018) and the reviewer find each part of a slice without searching.

A missing request is reported on the namespace of the slice; a missing handler or endpoint on its request; a misnamed, misplaced or extra type, an endpoint of a reaction slice or of a system command included, on its declaration; an HTTP mapping that sends a system command on its mapping method. A system command that no type of its module sends is reported on its declaration, at the end of the compilation: in the IDE, by full solution analysis. File paths are relative to the project.

## Bad example

```csharp
// src/MyApp/Features/Bookings/ArchiveBooking/ArchiveBooking.cs
namespace MyApp.Features.Bookings.ArchiveBooking;

public sealed record ArchiveCommand(Guid BookingId) : ICommand<bool>;                 // not named after the slice

public sealed record RestoreBookingCommand(Guid BookingId) : ICommand<bool>;          // a second use case

internal sealed class ArchiveRules : AbstractValidator<ArchiveCommand> { ... }         // not named after the slice

internal sealed class ArchiveHandler : IRequestHandler<ArchiveCommand, bool> { ... }   // not named after the slice

// no ArchiveBookingEndpoint

// src/MyApp/Features/Bookings/ConfirmBooking.cs: the ConfirmBooking slice, outside its folder
namespace MyApp.Features.Bookings.ConfirmBooking;

// src/MyApp/Features/Bookings/NotifyOnBookingConfirmed/NotifyOnBookingConfirmed.cs
internal sealed class NotifyHandler : IDomainEventHandler<BookingConfirmed> { ... }   // not named after the slice

// src/MyApp/Features/Feeds/CollectFeeds/CollectFeeds.cs: sent by nothing but its endpoint
public sealed record CollectFeedsCommand : ISystemCommand<int>;
```

## How to fix

1. Misnamed request, handler, validator or endpoint: rename it after the slice, as the fix says, and update its uses (the module registrations, the tests).
2. Second request: it is another use case. Create its slice `Features/<Module>/<UseCase>/` and move the request, its handler, its validator and its endpoint there, with their tests (HS018).
3. No request: declare the command or the query of the use case, or, for a reaction to a domain event, its domain event handler. If the folder holds no use case but types the slices of the module share, move them to the namespace and the folder of the module, `MyApp.Features.<Module>`, as the public contract of the module.
4. No handler or no endpoint: declare it in the slice, then register the handler in `<Module>Module.cs` and call the `Map` method of the endpoint from its group.
5. Request, handler or validator outside a slice: move it into the slice of its use case, folder and namespace, as the fix names them.
6. Domain event handler outside a reaction slice, beside a request, or second handler of a reaction slice: move it into a reaction slice of its own, named after what it does, such as `NotifyOnBookingConfirmed`, and register it in `<Module>Module.cs` as `IDomainEventHandler<TEvent>`. A handler of several events becomes one reaction slice per event. A reaction slice has no endpoint: an HTTP entry point is a command slice of its own.
7. File outside the folder of its slice, or type in the wrong namespace: move the file under `Features/<Module>/<Slice>/`, or give the type the namespace of the folder it is in.
8. System command with an endpoint, or sent by an HTTP mapping: remove the endpoint and its call from `<Module>Module.cs`. If the use case really needs an HTTP entry point, such as a manual trigger, it is a command slice of its own, whose command implements `ICommand<TResponse>`.
9. System command that no type of its module sends: send it from the type that should run it, in its module. A periodic task is registered in `<Module>Module.cs` with `services.AddRecurringCommand<TCommand, TResponse>(section, interval)`, which sends a new command at each interval, and which `dotnet new hardslice-command --every <interval>` prints, or with a `RecurringSchedule` for a daily one, `RecurringSchedule.DailyAt(time, timeZone)`, which `--daily-at <hh:mm>` prints. Any other trigger is a hosted service in the folder of the slice that creates the command and sends it through `IMediator` in a scope of its own, registered in `<Module>Module.cs`. A command that nothing needs to send is removed, with its slice and its tests.
10. Run the check script again.

## Skill

The message names the `add-slice` skill, in `.claude/skills/` and `.agents/skills/`: it generates a slice and its tests with `dotnet new hardslice-command` or `hardslice-query`, registers the slice and fills it, which gives it the shape this rule expects. For a slice that already exists, apply the fix above as its steps do, then run the check script.

## Forbidden workarounds

These mechanisms are not valid fixes for HS004. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS004`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS004.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- Implementing `IRequest<T>` directly, or dropping `ICommand<T>`, `IQuery<T>` or `IDomainEventHandler<TEvent>` from a type, so that the rule no longer recognizes it.
- An empty handler, endpoint or request declared only to complete the slice, or an endpoint its module never calls.
- Implementing `ICommand<T>` instead of `ISystemCommand<T>` for a command that only the application sends, which then needs an endpoint and exposes the use case, or a type declared only to create a system command that nothing runs.
- Marking a file `<auto-generated>`, naming it `.g.cs` or setting `generated_code = true` so that the rule skips it.
- Changing the contracts of `hardslice.json`.

## What the rule does not detect

- The name and the number of the files of a slice: one file or several, any names, as long as they are under its folder.
- A request, a handler or an endpoint declared in generated code only: it is not checked, but it counts for its slice.
- A handler or a validator of a slice declared in another slice: HS016 reports it, HS004 does not report it again.
- A request named after its slice but that does not match its use case.
- Whether the type that sends a system command runs: a hosted service that the module never registers, or a method that nothing calls, counts as a sender. A type of another module, or `Program`, does not.
- A slice without endpoint while the messaging contracts of `hardslice.json` are unusable: it cannot be told from a reaction slice, and HS900 reports the configuration.
- Whether a reaction slice is named after what it does: `NotifyOnBookingConfirmed` is a convention, the rule checks only that its handler is named after it.
- Whether a domain event handler stays in the transaction: an external effect, such as an e-mail or an HTTP call, is a review matter. A request sent through `IMediator` fails at runtime.

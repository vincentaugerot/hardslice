# HS009: a domain event is a record

Severity: error. Reported at build time by `HardSlice.Analyzers`, in the `Recommended` and `All` analysis modes. Not reported in test projects.

## Rule

A domain event is a type that implements `IDomainEvent`, directly, through a base class or through a derived interface such as `IBookingEvent : IDomainEvent`. Every domain event that is a class or a struct is declared as a `record class` (`record`) or a `record struct`.

- The rule applies wherever the event is declared: in the domain project, and in the web project or any other project that implements `IDomainEvent`. It runs in the project that declares the event.
- A generic event such as `EntityChanged<TEntity>`, an abstract base event and the events that derive from it are records too.
- An interface that derives from `IDomainEvent` groups events and is not one: it is not reported.

HS009 checks the shape of the event, not its immutability: a record can still declare a property with a public `set` accessor, and the rule accepts it. Declare the values of the event as positional parameters, which a record exposes as `init` properties.

A type that is both an entity and a domain event is reported by HS901 only, which asks for one role per type.

## Why

A domain event records a fact that has happened: `BookingConfirmed` carries the booking, the room and the period at the moment of the confirmation. A fact is a value. Two events with the same data are the same fact, and nothing changes it once it is raised: handlers in other slices and other modules read it, maybe later, maybe after a retry, and each must see what the aggregate recorded.

A `record` says so in its declaration and gives that behavior for free: equality by value, positional parameters that are set once, `with` to derive a corrected copy, and a readable `ToString()` in logs and tests. A class compares by reference, invites setters and constructors that diverge from the data, and lets a handler change the event that the next handler reads.

## Diagnostic

```text
HS009: domain event 'BookingConfirmed' is a class. Domain events are records. Fix: declare it as 'public sealed record BookingConfirmed(...) : IDomainEvent'. Skill: add-domain-event. Doc: 'docs/rules/HS009.md'.
```

The diagnostic is reported on the name of the type. The fix keeps its accessibility, its modifiers and its base list. The other forms read:

```text
HS009: domain event 'BookingCancelled' is a class. ... Fix: declare it as 'public sealed record BookingCancelled(...) : IBookingEvent'. ...
HS009: domain event 'BookingEvent' is a class. ... Fix: declare it as 'public abstract record BookingEvent(...) : IDomainEvent'. ...
HS009: domain event 'BookingPaid' is a struct. ... Fix: declare it as 'public readonly record struct BookingPaid(...) : IDomainEvent'. ...
HS009: domain event 'EntityChanged<TEntity>' is a class. ... Fix: declare it as 'public sealed record EntityChanged<TEntity>(...) : IDomainEvent'. ...
```

## Bad example

```csharp
// src/MyApp.Domain/Bookings/Events/BookingConfirmed.cs
public sealed class BookingConfirmed : IDomainEvent
{
    public BookingConfirmed(BookingId bookingId, Guid roomId)
    {
        BookingId = bookingId;
        RoomId = roomId;
    }

    public BookingId BookingId { get; }

    public Guid RoomId { get; set; }
}
```

## Good example

```csharp
// src/MyApp.Domain/Bookings/Events/BookingConfirmed.cs
public sealed record BookingConfirmed(BookingId BookingId, Guid RoomId, BookingPeriod Period) : IDomainEvent;

// A family of events shares its data through an abstract base record.
public abstract record BookingEvent(BookingId BookingId) : IDomainEvent;

public sealed record BookingCancelled(BookingId BookingId, string Reason) : BookingEvent(BookingId);

// A small event can be a value type.
public readonly record struct BookingPaid(BookingId BookingId, decimal Amount) : IDomainEvent;
```

## How to fix

1. Replace `class` with `record`, or `struct` with `record struct`, as the diagnostic shows, and keep `sealed` or `abstract`.
2. Move the values of the event to positional parameters: `public sealed record BookingConfirmed(BookingId BookingId, Guid RoomId) : IDomainEvent;`. Remove the constructor that only assigned them, and the setters.
3. If the event derives from a base event, make the base a record too: a record can only derive from a record. Pass the shared values to it, such as `BookingCancelled(...) : BookingEvent(BookingId)`.
4. Keep the places that raise the event unchanged: `new BookingConfirmed(booking.Id, roomId, period)` calls the positional constructor.
5. Run the check script again.

## Skill

The message names the `add-domain-event` skill, in `.claude/skills/` and `.agents/skills/`: it generates a domain event, a record named as a past fact, raises it from the aggregate and adds the reaction slice that handles it, so that a module reacts to another without using its types. For an event that already exists, apply the fix above as its steps do, then run the check script.

## Forbidden workarounds

These mechanisms are not valid fixes for HS009. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS009`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS009.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- Removing `IDomainEvent` from the event, or implementing an unrelated interface instead, so that the event is no longer classified, or changing the contracts of `hardslice.json`.
- Declaring the event in generated code, with an `<auto-generated>` header: generated code is analyzed.
- Wrapping a class in a record that holds it as a property: the record only carries the mutable class.

## What the rule does not detect

- Immutability: a record with a public `set` accessor, a mutable collection or a mutable class as a property is accepted. Keep the values of an event as positional parameters of immutable types.
- A type that carries a fact without implementing `IDomainEvent`: HardSlice classifies types only by their contracts.
- A type that is also an entity: HS901 reports it instead.
- Events when `hardslice.json` or its `domainEvent` contract is unusable: HS900 reports the configuration instead.
- Test projects.

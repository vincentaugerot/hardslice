# HS000: every suppression of a HardSlice rule carries its justification

Severity: error. Reported at build time by `HardSlice.Analyzers`, in every analysis mode, in every project, test projects and generated code included. HS000 itself cannot be suppressed or lowered.

## Rule

A HardSlice rule is suppressed in source only with a comment that gives the reason, on the line of the suppression or on the line above:

```csharp
// hardslice-justification: <reason>
```

The reason holds at least ten characters that are not spaces. HS000 checks:

- `#pragma warning disable` of an HS identifier, such as `HS016`, whether or not a `#pragma warning restore` follows. Each HS identifier of the directive is reported; the identifiers of other analyzers and the numbers of compiler warnings are ignored. A `#pragma warning disable` without identifier disables every warning, the HardSlice rules included: it needs a justification too, except in generated code, whose generators write it at the top of their output.
- `[SuppressMessage]` and `[UnconditionalSuppressMessage]` of an HS identifier, `HS016` or `HS016:<name>`, recognized by their symbols in `System.Diagnostics.CodeAnalysis`, through an alias too, with any category, on an assembly, a module, a type, a member, a parameter or a return value. Their `Justification` property is not enough: the comment is required, so that the reason appears in the diff next to the suppression.

A suppression of HS000 itself, `#pragma warning disable HS000` or `[SuppressMessage("HardSlice.Architecture", "HS000")]`, is always reported, even with a justification. Neither it, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS000.severity` nor an analysis mode turns HS000 off.

The compiler compares rule identifiers by their case and as written: `hs016` or `" HS016"` suppresses nothing, and HS000 does not report it.

## Why

A suppression makes a HardSlice rule silent where it is written: the build passes, and a reviewer reading the diff sees only a line among others. The rules exist so that an agent or a developer under pressure fixes the code instead of hiding it. A suppression is sometimes right, for example a generated file or a decision of a maintainer for a migration in progress; then the reason belongs next to it, where the reviewer reads it and where the next reader learns why the rule does not apply.

The justification is a comment and not the `Justification` property of the attribute so that the same form serves pragmas and attributes, and so that a search for `hardslice-justification` lists every exception of the solution.

## Diagnostic

```text
HS000: '#pragma warning disable HS016' in 'CancelBooking.cs' has no justification. A HardSlice rule is suppressed only with a reason a reviewer can read. Fix: remove the suppression and fix the code; if a maintainer approved it, add '// hardslice-justification: <reason>' on the line above. Skill: fix-architecture-violation. Doc: 'docs/rules/HS000.md'.
```

The diagnostic names the suppression and its file. For an attribute, a reason too short, a pragma without identifier or a suppression of HS000:

```text
HS000: '[SuppressMessage("HardSlice.Architecture", "HS016")]' in 'CancelBooking.cs' has no justification. ...
HS000: '#pragma warning disable HS010' in 'Booking.cs' has a justification of fewer than 10 characters. ... Fix: remove the suppression and fix the code; if a maintainer approved it, give the reason in at least 10 characters after '// hardslice-justification:'. ...
HS000: '#pragma warning disable' in 'Booking.cs' disables every warning, the HardSlice rules included, and has no justification. ... Fix: name the warnings it disables; for a HardSlice rule, remove the suppression and fix the code; ...
HS000: '#pragma warning disable HS000' in 'Booking.cs' suppresses HS000, which no justification allows. ... Fix: remove it; HS000 reports every suppression of a HardSlice rule that has no justification. ...
```

## Bad example

```csharp
// src/MyApp/Features/Bookings/CancelBooking/CancelBooking.cs
#pragma warning disable HS016
internal sealed class CancelBookingHandler(ConfirmBooking.ConfirmBookingHandler confirm)
    : IRequestHandler<CancelBookingCommand, bool>
{
    // ...
}

// src/MyApp.Domain/Bookings/Booking.cs
[SuppressMessage("HardSlice.Architecture", "HS007", Justification = "EF Core")]
public string Status { get; set; }

// hardslice-justification: needed
#pragma warning disable HS010
```

## Good example

The code is fixed, and no suppression remains:

```csharp
// src/MyApp/Features/Bookings/CancelBooking/CancelBooking.cs
internal sealed class CancelBookingHandler(AppDbContext db) : IRequestHandler<CancelBookingCommand, bool>
{
    // ...
}
```

When a maintainer approved an exception, the reason is next to it:

```csharp
// hardslice-justification: generated by the payment SDK, which reads the clock itself; approved in review #142
#pragma warning disable HS010
```

```csharp
[SuppressMessage("HardSlice.Architecture", "HS011")] // hardslice-justification: legacy console entry point, removed with #158
```

## How to fix

1. Remove the suppression and run the check script: fix the diagnostic it was hiding with the sheet of its rule, as for any other HardSlice failure.
2. Only when a maintainer explicitly approved the exception: add `// hardslice-justification: <reason>` on the line of the suppression or on the line above, with the reason and, if any, where the decision was made.
3. For `#pragma warning disable` without identifier, name the warnings it disables: `#pragma warning disable CS0618`. A pragma limited to the warnings of the compiler or of other analyzers needs no justification.
4. For a suppression of HS000: remove it. There is no exception to HS000.
5. Run the check script again.

## Skill

The message names the `fix-architecture-violation` skill, in `.claude/skills/` and `.agents/skills/`: it reads the diagnostic and this sheet, applies the first fix above that matches, runs the check script again, and stops to explain the conflict when only a workaround would make it pass.

## Forbidden workarounds

These mechanisms are not valid fixes for HS000. Do not use them to make the build pass:

- `#pragma warning disable HS000`, `[SuppressMessage]` of HS000, `<NoWarn>`, `<WarningsNotAsErrors>` or `dotnet_diagnostic.HS000.severity` in `.editorconfig` or `.globalconfig`: none turns HS000 off, and the first two are reported themselves.
- A justification written only to silence HS000, such as `// hardslice-justification: needed for the build`, without a decision of a maintainer. HS000 does not judge the reason: the reviewer does.
- Moving the suppression out of the source: `<NoWarn>HS016</NoWarn>`, `dotnet_diagnostic.HS016.severity = none` in `.editorconfig` or a `.globalconfig`, `<WarningsNotAsErrors>`, a lower `HardSliceAnalysisMode`, or turning the analyzers off. HS000 does not see them, but each one is a forbidden workaround of the rule it hides, listed in `AGENTS.md`.
- Spelling the identifier differently, such as `hs016`: it suppresses nothing.
- Adding an `<auto-generated>` header to a file, or naming it `*.g.cs`, to write a `#pragma warning disable` without identifier there: the pragmas that name an HS rule are checked in generated code as anywhere else.

## What the rule does not detect

- Suppressions outside the source: `<NoWarn>`, `<WarningsNotAsErrors>`, the severities of `.editorconfig` and `.globalconfig`, `HardSliceAnalysisMode`, `<RunAnalyzers>`. The analysis modes turn rules off through a global config themselves, and a setting of the solution cannot be told apart from one of HardSlice reliably. These files, `hardslice.json`, the architecture tests and the check scripts are protected by review and by the CI of the solution.
- A false or vague reason: HS000 checks the form and the length of the justification, never its truth. It stays visible in review.
- A justification that serves several suppressions: each pragma or attribute needs its own, on its line or the line above, but one comment covers every identifier of the same directive and every attribute of the same line.
- A suppression written by a `DiagnosticSuppressor` of another analyzer package: HardSlice adds none, and a new package goes through review.
- Code in an inactive `#if` region, which suppresses nothing.
- A `#pragma warning disable` without identifier in generated code: a file with an `<auto-generated>` header or named `*.g.cs`, `*.designer.cs` or `*.generated.cs`, such as the output of the `[GeneratedRegex]` generator. Adding such a header or name to a file written by hand only to hide a rule is a forbidden workaround.

# HS003: endpoints never reach the database

Severity: error. Reported at build time by `HardSlice.Analyzers`, in every analysis mode, on the endpoint. Not reported in test projects.

## Rule

An endpoint sends a command or a query through `IMediator` and turns its response into `TypedResults`. It never receives, injects or obtains a database access: only the handler of the request reaches `AppDbContext`.

An endpoint is the delegate given to a mapping method of ASP.NET Core, recognized by its symbol: `MapGet`, `MapPost`, `MapPut`, `MapDelete`, `MapPatch`, `MapMethods`, `Map` and `MapFallback`, on an `IEndpointRouteBuilder`, a `RouteGroupBuilder` or the `WebApplication`. The delegate is a lambda, an anonymous method, or a static or instance method group declared in the project. The rule applies everywhere in the project: slices, modules and `Program.cs`.

In the body of the endpoint, its lambdas and local functions included, HS003 reports any parameter, local, field, property, call result, object creation or cast whose type is or derives from:

| Type | Package |
|---|---|
| `DbContext`, such as `AppDbContext`, `DbSet<T>`, `IDbContextFactory<T>`, `DatabaseFacade` | EF Core |
| `DbConnection`, `IDbConnection`, `DbDataSource`, such as `NpgsqlConnection` and `NpgsqlDataSource` | ADO.NET |

## Why

An endpoint that queries the database skips everything the pipeline gives a request: validation before any work, one transaction per command that rolls back on failure, logs, and a handler that integration tests cover. Its business logic also escapes the aggregate. Data access in an endpoint is the first shortcut a hurried change takes; the handler is the only place for it.

## Diagnostic

```text
HS003: endpoint 'GET /' in slice 'Bookings/ListBookings' uses 'AppDbContext' (parameter 'db'). Endpoints never reach the database. Fix: move the data access into the handler of a query and send the query with IMediator. Doc: 'docs/rules/HS003.md'.
```

The endpoint is named by its HTTP method and its route as written at the mapping, with the prefixes of the groups mapped in the same method; a group received as a parameter adds nothing. The symbol in parentheses is where the database enters the endpoint. The diagnostic is reported once per endpoint and per symbol: the members reached through it, such as `db.Bookings` or `db.SaveChangesAsync()`, are part of the same access.

## Bad example

```csharp
// src/MyApp/Features/Bookings/ListBookings/ListBookings.cs
internal static class ListBookingsEndpoint
{
    public static void Map(RouteGroupBuilder group) =>
        group.MapGet("/", async (AppDbContext db, CancellationToken cancellationToken) =>
            TypedResults.Ok(await db.Set<Booking>().AsNoTracking().Select(booking => booking.Id.Value).ToListAsync(cancellationToken)));
}
```

Obtaining the context does not hide it: `context.RequestServices.GetRequiredService<AppDbContext>()`, an `IDbContextFactory<AppDbContext>`, a field of the class whose method is mapped, or an injected `NpgsqlDataSource` are reported the same way.

## Good example

```csharp
// src/MyApp/Features/Bookings/ListBookings/ListBookings.cs
public sealed record ListBookingsQuery : IQuery<IReadOnlyList<Guid>>;

internal sealed class ListBookingsHandler(AppDbContext db) : IRequestHandler<ListBookingsQuery, IReadOnlyList<Guid>>
{
    public async Task<IReadOnlyList<Guid>> Handle(ListBookingsQuery query, CancellationToken cancellationToken) =>
        await db.Set<Booking>().AsNoTracking().Select(booking => booking.Id.Value).ToListAsync(cancellationToken);
}

internal static class ListBookingsEndpoint
{
    public static void Map(RouteGroupBuilder group) =>
        group.MapGet("/", async (IMediator mediator, CancellationToken cancellationToken) =>
            TypedResults.Ok(await mediator.Send(new ListBookingsQuery(), cancellationToken)));
}
```

## How to fix

1. Declare the request of the slice: an `IQuery<TResponse>` when the endpoint only reads, an `ICommand<TResponse>` when it changes state. A command with parameters gets its validator.
2. Move the data access, unchanged, into the handler of that request, which receives `AppDbContext` in its constructor. A command handler never calls `SaveChangesAsync`: the pipeline saves and commits.
3. Register the handler (and the validator) in `<Module>Module.cs`, and make the endpoint send the request through `IMediator`, keeping only the HTTP concerns: binding, `TypedResults`, status codes.
4. A technical endpoint of `Program.cs` that checks the database, such as a health check, uses `AddHealthChecks().AddDbContextCheck<AppDbContext>()` and `MapHealthChecks` instead of a hand-written endpoint.
5. Run the check script again.

## Forbidden workarounds

These mechanisms are not valid fixes for HS003. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS003`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, or `dotnet_diagnostic.HS003.severity` in `.editorconfig` or `.globalconfig`.
- Moving the data access into a static helper, an extension method or a service that the endpoint calls, only because HS003 does not follow calls. The access then still bypasses validation and the transaction.
- Storing the endpoint delegate in a variable or a field, or resolving the context as `object` and using it through `dynamic` or reflection, only to hide it from the rule.
- Injecting `IServiceProvider` and resolving a handler, a repository or the context directly instead of sending the request through `IMediator`.
- Moving the endpoint into a controller only to escape the rule.

## What the rule does not detect

- Data access in a method, a service or a repository that the endpoint calls: the methods it calls are not followed.
- An endpoint whose delegate comes from a variable, a field, a call, or a method of another assembly: it cannot be read where it is mapped.
- A parameter whose type only wraps a database type, such as `Lazy<AppDbContext>` or `Func<AppDbContext>`, as long as the endpoint never obtains the context from it (`lazy.Value`, `factory()`).
- MVC controllers.
- In the IDE, a method group declared in another file is reported on the mapping, where the endpoint is analyzed.

# HS007: the state of an entity is never written from outside

Severity: error. Reported at build time by `HardSlice.Analyzers`, in every analysis mode. Not reported in test projects.

## Rule

An entity implements `IEntity`, directly or through a base class: aggregate roots (`IAggregateRoot`) and child entities alike. Code outside its assembly reads its state, and changes it only by calling its methods. HS007 reports, in the project that declares the entity:

- an instance property whose `set` or `init` accessor is public: `public BookingStatus Status { get; set; }`, `public Guid RoomId { get; init; }`;
- a public instance field that is not `readonly`: `public DateTimeOffset? CancelledAt;`;
- the properties declared by the positional parameters of a record used as an entity: `public sealed record Room(Guid Id, string Name) : IAggregateRoot` gives both a public `init` accessor;
- a setter that implements a public interface, explicitly or implicitly: with `BookingStatus IEditableBooking.Status { get; set; }`, `((IEditableBooking)booking).Status = BookingStatus.Cancelled;` writes the state without any domain method;
- the public setters and fields inherited from a base class that is not an entity, or that is declared in another project: they are reported on the declaration of the entity. A base class that is itself an entity of the same project reports them once, on its own declaration.

Accessibility is effective: an accessor counts only when another assembly can reach it. `private`, `protected`, `internal`, `protected internal` and `private protected` accessors are accepted, as are the members of an internal entity and the implementation of an internal interface. Static members, `readonly` fields and constants are not state of the instance.

DTOs, commands, queries, domain events and value objects, such as `BookingPeriod` or `BookingId`, are not entities: their public `init` accessors are out of the rule.

## Why

An entity protects its invariants in its methods: `Booking.Confirm` refuses a booking that overlaps another and raises `BookingConfirmed`, `Booking.Cancel` refuses to cancel a booking twice. A public setter lets any handler, endpoint or test change the same state without these checks: a booking is cancelled twice, a period is replaced without the overlap check, and the rule ends up copied in every slice that needs it, each copy slightly different. The domain becomes a bag of data and the business logic slides into the handlers.

The rule asks for no more than encapsulation: a setter the outside cannot reach. It does not prove that the domain is rich; it makes sure that its methods are the only way to change it.

## Diagnostic

```text
HS007: entity 'Booking' exposes 'Status' with a public setter. The state of an entity changes only through its methods, which protect its invariants. Fix: make the setter private and change the state in a domain method, such as 'Booking.Cancel()'. Skill: extract-to-domain. Doc: 'docs/rules/HS007.md'.
```

The diagnostic is reported on the `set` or `init` keyword of the accessor, on the field or on the positional parameter. A member inherited from a base class, or an interface setter implemented by it, is reported on the declaration of the entity. The fix names the first public method of the entity, when it declares one. The other forms read:

```text
HS007: entity 'Booking' exposes 'RoomId' with a public init accessor. ...
HS007: entity 'Booking' exposes 'CancelledAt' as a public field that is not readonly. ...
HS007: entity 'Room' exposes 'Name', declared by a positional parameter, with a public init accessor. ...
HS007: entity 'Booking' exposes 'UpdatedAt', inherited from 'AuditedEntity', with a public setter. ...
HS007: entity 'Booking' lets 'IEditableBooking.Status' be set from outside. The state of an entity changes only through its methods, which protect its invariants. Fix: remove the setter from the public interface and change the state in a domain method, such as 'Booking.Cancel()'. Skill: extract-to-domain. Doc: 'docs/rules/HS007.md'.
```

## Bad example

```csharp
// src/MyApp.Domain/Bookings/Booking.cs
public sealed class Booking : IAggregateRoot
{
    public BookingId Id { get; init; }

    public BookingStatus Status { get; set; }
}

// src/MyApp/Features/Bookings/CancelBooking/CancelBooking.cs
booking.Status = BookingStatus.Cancelled; // even when it is already cancelled
```

## Good example

```csharp
// src/MyApp.Domain/Bookings/Booking.cs
public sealed class Booking : IAggregateRoot
{
    private BookingStatus _status;

    public BookingId Id { get; }

    public BookingStatus Status => _status;

    public void Cancel()
    {
        if (_status == BookingStatus.Cancelled)
            throw new DomainException($"Booking '{Id}' is already cancelled.");

        _status = BookingStatus.Cancelled;
    }
}

// src/MyApp/Features/Bookings/CancelBooking/CancelBooking.cs
booking.Cancel();
```

## How to fix

1. Make the setter `private`, or remove it when only the constructor sets the value: `public Guid RoomId { get; }`.
2. Move the change into a method of the entity named after the business operation, such as `Cancel`, `Reschedule` or `Rename`, which checks the invariants and raises the domain events. The handler calls it.
3. For a value set at creation, take it as a parameter of the constructor or of the static factory method, such as `Booking.Confirm`. EF Core sets private setters and backing fields when it loads an entity: no public setter is needed for persistence.
4. A public field becomes a private field, read through a property without a setter.
5. A record used as an entity declares its properties in its body, with a private setter: `public string Name { get; private set; } = Name;`. Prefer a class for an entity.
6. A setter inherited from a base class, such as an audit base, becomes `protected` or `private` in the base class; the entity changes the value in its own methods.
7. A setter required by an interface is removed from the interface. When only the domain project needs it, for example to restore a stored state, declare the interface `internal`.
8. Run the check script again.

## Skill

The message names the `extract-to-domain` skill, in `.claude/skills/` and `.agents/skills/`: it moves the business rule that a slice holds, or that slices share, into the aggregate with its unit test, makes each slice call the method of the domain, then runs the check script.

## Forbidden workarounds

These mechanisms are not valid fixes for HS007. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS007`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS007.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- A public method that only assigns its parameter, such as `SetStatus(BookingStatus status)`: it is a setter under another name. A domain method names a business operation and checks its invariants.
- Writing the state by reflection, or exposing it through a public mutable object, such as a `List<T>` a caller can change.
- `[InternalsVisibleTo]` towards the web project or the slices, to let them use an `internal` setter.
- Removing `IEntity` or `IAggregateRoot` from the entity, turning it into a DTO, or changing the contracts of `hardslice.json`.

## What the rule does not detect

- A write by reflection, by `Unsafe`, or through a public mutable collection or object that the entity exposes.
- A public method that only assigns its parameter: the rule reads accessors, not the content of methods.
- An internal setter reached by another project through `[InternalsVisibleTo]`.
- A child entity that does not implement `IEntity`, such as an owned type: HardSlice classifies types only by their contracts, and HS902 asks for them on the entities EF Core maps.
- Entities when `hardslice.json` or its `entity` contract is unusable: HS900 reports the configuration instead.
- Test projects.

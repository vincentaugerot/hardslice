# HS005: a command handler never returns an entity

Severity: error. Reported at build time by `HardSlice.Analyzers`, in the `Recommended` and `All` analysis modes. Not reported in test projects.

## Rule

A command handler implements `IRequestHandler<TCommand, TResponse>`, directly or through a base class, for a request that implements `ICommand<TResponse>`. Its `TResponse` returns an identifier, a DTO of values or nothing: never an entity, an aggregate root (`IAggregateRoot`) or a child entity (`IEntity`).

HS005 reports the handler when it reaches an entity from `TResponse` by following:

- the type itself, `Booking?` included;
- the elements of an array: `Booking[]`;
- the type arguments of any constructed generic type: `List<Booking>`, `IReadOnlyList<BookingLine>`, `Dictionary<Guid, Booking>`, `Result<Booking>`;
- the elements of a tuple: `(BookingId, Booking)`;
- the public instance properties and fields of a DTO, at any depth: `ConfirmationDto` whose property `Booking` is the entity, or whose property `Lines` is an `IReadOnlyList<BookingLine>`.

A DTO is followed when it is declared in the domain, in the project of the handler or in a project that references the domain: only there can it hold an entity. The types of the framework and of the libraries are not followed. A DTO that references itself, or two DTOs that reference each other, are followed once.

Value objects of the domain, such as `BookingId` or `BookingPeriod`, are followed like DTOs: they hold values, so they are valid responses. Query handlers are out of the rule: HS006 checks what they read.

## Why

A command changes state inside one transaction, and its handler is the only code that holds the aggregate while it is consistent. An entity returned to the endpoint leaves that boundary: the endpoint, a pipeline behavior or the JSON serializer can read lazy navigations after the transaction, call a method that changes the aggregate outside any transaction, or expose internal state, such as its domain events, in the HTTP response. The response also couples the API contract to the shape of the domain: renaming a property of `Booking` breaks a client.

An identifier lets the caller read the state it needs through a query, which reads without tracking. A DTO of values says exactly what the command returns and keeps the domain free to change.

## Diagnostic

```text
HS005: handler 'ConfirmBookingHandler' of command 'ConfirmBookingCommand' returns 'ConfirmationDto', whose property 'Booking' holds the entity 'Booking'. Command handlers return an identifier, a DTO of values or nothing. Fix: return 'BookingId', or a DTO built from the entity's values. Skill: fix-architecture-violation. Doc: 'docs/rules/HS005.md'.
```

The diagnostic is reported on the declaration of the handler. It names the command, the response, the path to the entity and the entity; the fix names the type of the entity's `Id` property when it has one. The other forms read:

```text
HS005: handler 'ConfirmBookingHandler' of command 'ConfirmBookingCommand' returns the entity 'Booking'. ...
HS005: handler 'ConfirmBookingHandler' of command 'ConfirmBookingCommand' returns 'Result<Booking>', which holds the entity 'Booking'. ...
HS005: handler 'AddLinesHandler' of command 'AddLinesCommand' returns 'IReadOnlyList<LinesDto>', whose property 'LinesDto.Lines' holds the entity 'BookingLine'. ...
```

## Bad example

```csharp
// src/MyApp/Features/Bookings/ConfirmBooking/ConfirmBooking.cs
public sealed record ConfirmBookingCommand(Guid RoomId, DateTimeOffset Start, DateTimeOffset End) : ICommand<ConfirmationDto>;

public sealed record ConfirmationDto(Guid RoomId, Booking Booking);

internal sealed class ConfirmBookingHandler(AppDbContext db) : IRequestHandler<ConfirmBookingCommand, ConfirmationDto>
{
    public async Task<ConfirmationDto> Handle(ConfirmBookingCommand command, CancellationToken cancellationToken)
    {
        // ...
        return new ConfirmationDto(command.RoomId, booking);
    }
}
```

## Good example

```csharp
// src/MyApp/Features/Bookings/ConfirmBooking/ConfirmBooking.cs
public sealed record ConfirmBookingCommand(Guid RoomId, DateTimeOffset Start, DateTimeOffset End) : ICommand<Guid>;

internal sealed class ConfirmBookingHandler(AppDbContext db) : IRequestHandler<ConfirmBookingCommand, Guid>
{
    public async Task<Guid> Handle(ConfirmBookingCommand command, CancellationToken cancellationToken)
    {
        // ...
        return booking.Id.Value;
    }
}

// Or, when the caller needs values right away: a DTO built from the values of the entity, never holding it.
public sealed record ConfirmationDto(Guid Id, Guid RoomId, DateTimeOffset Start, DateTimeOffset End);
```

## How to fix

1. Return the identifier of the entity, a `Guid`, when the caller only needs to find it again: the endpoint answers `201 Created` with its location, and the client reads it with a query of the module.
2. When the caller needs values right away, declare a DTO in the slice whose properties are values (identifiers, scalars, value objects of the domain, other DTOs of values) and build it from the entity in the handler.
3. A child entity, such as a line of a booking, is returned by its identifier or as a DTO of its values too, collections included: `IReadOnlyList<BookingLineDto>`, never `IReadOnlyList<BookingLine>`.
4. A command with nothing to return returns `bool`, `false` answered with 404 when its aggregate does not exist, as `dotnet new hardslice-command --response none` generates it.
5. Run the check script again.

## Skill

The message names the `fix-architecture-violation` skill, in `.claude/skills/` and `.agents/skills/`: it reads the diagnostic and this sheet, applies the first fix above that matches, runs the check script again, and stops to explain the conflict when only a workaround would make it pass.

## Forbidden workarounds

These mechanisms are not valid fixes for HS005. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS005`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS005.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- Typing the entity as `object`, `dynamic`, an interface the entity implements other than its contracts, or a non-generic collection, only because HS005 follows declared types.
- Hiding the entity in a non-public member of the DTO, in a subtype known only at runtime, or in a type of a library that the rule does not follow.
- Turning the command into a query, or dropping `ICommand<T>` from it, so that the rule no longer recognizes its handler.
- Removing `IEntity` or `IAggregateRoot` from the entity, or changing the contracts of `hardslice.json`.

## What the rule does not detect

- An entity typed `object` or `dynamic`, stored in a non-generic collection such as `ArrayList`, held by a non-public member, or a subtype known only at runtime.
- An entity reached through a type of the framework or of a library that does not reference the domain, other than through its type arguments.
- A generic handler whose `TResponse` is an unconstrained type parameter: it cannot be analyzed. Constrained to `IEntity`, it is reported.
- An abstract base handler: it is reported through the concrete handlers derived from it.
- A child entity that does not implement `IEntity`, such as an owned type: HardSlice classifies types only by their contracts.
- Handlers when `hardslice.json` or its `entity`, `command` or `requestHandler` contract is unusable: HS900 reports the configuration instead.
- Test projects.

# HS015: slice endpoints stay in their slice, their group and their TypedResults

Severity: error. Reported at build time by `HardSlice.Analyzers`, in the `Recommended` and `All` analysis modes, on the endpoint. Not reported in test projects.

## Rule

Every endpoint mapped under `MyApp.Features`:

1. is mapped in its slice, by the `Map(RouteGroupBuilder group)` method of an `internal` endpoint class of the slice, never in `<Module>Module` or at the root of `Features`;
2. is mapped on a `RouteGroupBuilder`, the group its module creates with `MapGroup`, or a group nested in it, never on an `IEndpointRouteBuilder` or the `WebApplication`;
3. is registered by its module: the method of the slice that maps it is called by the type `<Module>Module` of its own module. A helper of the slice that maps an endpoint for the method the module calls is not registered: map the endpoints in the method the module calls;
4. returns a type of `Microsoft.AspNetCore.Http.HttpResults`, such as `Ok<T>`, `Created`, `NoContent` or `Results<Ok<T>, NotFound>`, directly or in a `Task<T>` or a `ValueTask<T>`, built with `TypedResults`.

An endpoint is recognized as HS003 recognizes it: the delegate given to `MapGet`, `MapPost`, `MapPut`, `MapDelete`, `MapPatch`, `MapMethods`, `Map` or `MapFallback` of ASP.NET Core, never by its name. Its return type is the one of the lambda, of the anonymous method, or of the method group. Endpoints outside `Features`, such as a technical endpoint of `Program.cs`, are not slice endpoints: HS015 does not check them, HS003 does.

## Why

A slice holds its whole use case, its endpoint included: reading the slice is enough to change it, and deleting its folder removes it. The module owns the route prefix of its endpoints through its group, and the policies (authorization, rate limiting, OpenAPI tags) that cover all of them; an endpoint mapped on the application escapes them silently. An endpoint that no module maps is dead code that looks alive. `TypedResults` put every response that the delegate of the endpoint returns in its signature: OpenAPI describes them, and a test or a reviewer sees a missing 404 without reading the body. `Results.Ok` and a returned DTO hide them behind `IResult` or a 200.

## Responses of the middleware

A response that the middleware writes before the delegate runs, such as the 401 or the 403 of an authorization policy or the 429 of rate limiting, is not in the signature of the endpoint, and HS015 does not ask for it. The signature of a protected endpoint stays `Task<Ok<T>>`: `Results<Ok<T>, UnauthorizedHttpResult>` would declare a response that the delegate never returns.

- The authentication scheme, its options and its policies are cross-cutting: they live in `src/MyApp/Shared/Http/` (HS017) and are registered from `Program.cs`, never by a module.
- A policy that covers every endpoint of a module goes on its group, in `<Module>Module.cs`: `endpoints.MapGroup("/schedule").RequireAuthorization(AdminKey.Policy)`.
- A policy that covers some endpoints of the module only, such as a protected write next to an open read, goes on the endpoint, in its slice: `group.MapPost("/versions", ...).RequireAuthorization(AdminKey.Policy)`.
- A `FallbackPolicy`, set in `Shared/Http` with `AddAuthorizationBuilder().SetFallbackPolicy(...)`, protects every endpoint that does not say `AllowAnonymous`: an endpoint that forgets its policy is then refused, not open.
- An integration test of the 401 stands for the signature: in the folder of the tests of the slice, next to its test of the 400, it sends the request without credentials, or with wrong ones, and asserts the status and that nothing changed.

## Diagnostic

```text
HS015: endpoint 'GET /{id:guid}' in slice 'Bookings/GetBooking' returns 'IResult'. A slice endpoint returns TypedResults, so its responses are part of its signature. Fix: build every response with TypedResults instead of Results, and declare them all as the return type of the endpoint, such as 'Task<Results<Ok<T>, NotFound>>'. Skill: add-slice. Doc: 'docs/rules/HS015.md'.
```

The other diagnostics of HS015 follow the same shape:

```text
HS015: endpoint 'POST /bookings' in slice 'Bookings/ConfirmBooking' is mapped on 'WebApplication', not on a group. ...
HS015: endpoint 'GET /bookings/{id:guid}' in 'BookingsModule' is mapped outside a slice. ...
HS015: endpoint 'POST /{id:guid}/archive' in slice 'Bookings/ArchiveBooking' is mapped by 'ArchiveBookingEndpoint.Map', which 'BookingsModule' never calls. ...
```

The endpoint is named as in HS003: its HTTP method and its route as written at the mapping, with the prefixes of the groups mapped in the same method. Each fault of an endpoint is one diagnostic. The registration is checked at the end of the compilation: in the IDE, it is reported by full solution analysis only.

## Bad example

```csharp
// src/MyApp/Features/Bookings/GetBooking/GetBooking.cs
internal static class GetBookingEndpoint
{
    public static void Map(RouteGroupBuilder group) =>
        group.MapGet("/{id:guid}", async (Guid id, IMediator mediator, CancellationToken cancellationToken) =>
            await mediator.Send(new GetBookingQuery(id), cancellationToken) is { } booking ? Results.Ok(booking) : Results.NotFound());
}

// src/MyApp/Features/Bookings/BookingsModule.cs
public static IEndpointRouteBuilder MapBookingsModule(this IEndpointRouteBuilder endpoints)
{
    var group = endpoints.MapGroup("/bookings");
    group.MapPost("/{id:guid}/archive", (Guid id) => TypedResults.NoContent());   // mapped outside its slice
    ConfirmBookingEndpoint.Map(group);
    return endpoints;                                                             // GetBookingEndpoint.Map is never called
}
```

## Good example

```csharp
// src/MyApp/Features/Bookings/GetBooking/GetBooking.cs
internal static class GetBookingEndpoint
{
    public static void Map(RouteGroupBuilder group) =>
        group.MapGet("/{id:guid}", async Task<Results<Ok<BookingDto>, NotFound>> (Guid id, IMediator mediator, CancellationToken cancellationToken) =>
            await mediator.Send(new GetBookingQuery(id), cancellationToken) is { } booking ? TypedResults.Ok(booking) : TypedResults.NotFound());
}

// src/MyApp/Features/Bookings/BookingsModule.cs
public static IEndpointRouteBuilder MapBookingsModule(this IEndpointRouteBuilder endpoints)
{
    var group = endpoints.MapGroup("/bookings");
    ConfirmBookingEndpoint.Map(group);
    GetBookingEndpoint.Map(group);
    ArchiveBookingEndpoint.Map(group);
    return endpoints;
}
```

## How to fix

1. Outside a slice: move the mapping into the `Map(RouteGroupBuilder group)` method of an `internal` endpoint class in the slice of its use case, `Features/<Module>/<Slice>/`, next to its request and its handler.
2. Not on a group: make that method receive the `RouteGroupBuilder` of the module and map the endpoint on it, or on a group nested in it with `group.MapGroup(...)`. The module creates its group with `MapGroup` and passes it to every slice.
3. Never called: in `<Module>Module.cs`, call the `Map` method of the slice with the group of the module, next to the other slices.
4. Not a `TypedResults` type: build every response with `TypedResults` (`TypedResults.Ok(dto)`, `TypedResults.NotFound()`, `TypedResults.Created(uri)`), never `Results` or a bare DTO. When the endpoint has several responses, declare them as the return type of the lambda, such as `async Task<Results<Ok<BookingDto>, NotFound>> (...) =>`: without it, C# cannot infer one type for both branches.
5. Run the check script again.

## Skill

The message names the `add-slice` skill, in `.claude/skills/` and `.agents/skills/`: it generates a slice and its tests with `dotnet new hardslice-command` or `hardslice-query`, registers the slice and fills it, which gives it the shape this rule expects. For a slice that already exists, apply the fix above as its steps do, then run the check script.

## Forbidden workarounds

These mechanisms are not valid fixes for HS015. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS015`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS015.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- Moving the endpoint out of `Features`, into `Program.cs` or another folder, only because HS015 checks slice endpoints only.
- Storing the endpoint delegate in a variable typed `Delegate` only to hide its return type from the rule.
- Writing a custom `IResult` type that does what `TypedResults` already does, or wrapping `Results.Ok` in a helper.
- Calling the `Map` method of a slice from a dead path of the module, such as an unreachable branch, only to count as registered.

## What the rule does not detect

- An endpoint whose delegate is stored in a variable or a field typed `Delegate`: its return type is unknown where it is mapped.
- Whether the module itself is mapped by `Program.cs`, or whether the call of the module runs.
- A custom result type that implements `IResult` is reported, even when it describes its responses: v0.2 accepts the types of `Microsoft.AspNetCore.Http.HttpResults` only.
- MVC controllers.

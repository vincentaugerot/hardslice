# HS900: the HardSlice configuration is usable

Severity: error. Reported at build time by `HardSlice.Analyzers`, each problem once per project, when a rule that needs the element in question is active. Not reported in test projects.

## Rule

The HardSlice rules on the domain and the messaging never guess the role of a type: they classify it by the contracts `hardslice.json` declares, at the solution root.

```json
"contracts": {
  "entity": "MyApp.Domain.IEntity, MyApp.Domain",
  "aggregateRoot": "MyApp.Domain.IAggregateRoot, MyApp.Domain",
  "domainEvent": "MyApp.Domain.IDomainEvent, MyApp.Domain",
  "command": "MyApp.Shared.Messaging.ICommand`1, MyApp",
  "query": "MyApp.Shared.Messaging.IQuery`1, MyApp",
  "requestHandler": "MyApp.Shared.Messaging.IRequestHandler`2, MyApp",
  "domainEventHandler": "MyApp.Shared.Messaging.IDomainEventHandler`1, MyApp"
}
```

The file starts with `"version": 1`, the version of its format: a later version of HardSlice may extend the format under another version, which this version of the analyzers reports instead of misreading it. `"$schema"` is accepted for editors. Any other key the format does not define is a problem: a misspelled key would otherwise turn a rule off without notice.

Each value is the metadata name of a type of the application, then the assembly that declares it. A contract is required in its declaring assembly and in every project that references it: `MyApp.Domain` does not reference `MyApp`, so it does not need `ICommand<T>`. The project that holds the slices, with the namespace `MyApp.Features`, needs every contract: there, a contract of an assembly that is neither the project nor one of its references is a problem.

HS900 reports, when an active rule needs the element:

- `hardslice.json` missing, given twice, not valid JSON, or holding a key it does not know;
- `version` missing or not a whole number, or a version these analyzers do not read: update `HardSlice.Analyzers` and the `hardslice.tool` local tool to the version that wrote the file;
- a contract key missing, or a value that is not `<metadata name>, <assembly>`;
- a required contract that its declaring assembly does not declare, for example after a rename or a move;
- in the project that holds the slices, a contract of an assembly that is neither the project nor one of its references, for example after a project is renamed;
- `hardslice.json` nested more than 64 levels deep;
- inconsistent contracts: `aggregateRoot` does not derive from `entity`, or two keys designate the same type.

## Why

Without its contracts, a rule would stay silent: an entity no longer recognized escapes every rule written for entities. HS900 stops the build instead, so the rules keep their reach.

## Diagnostic

```text
HS900: contract 'contracts.entity' of hardslice.json, 'MyApp.Domain.Entity', is not declared by assembly 'MyApp.Domain'. The contracts of hardslice.json classify the types checked by HS005, HS006, HS007, HS008, HS010, HS901 and HS902. Fix: restore the contract type 'MyApp.Domain.Entity' in project 'MyApp.Domain', or hardslice.json, from version control. Skill: fix-architecture-violation. Doc: 'docs/rules/HS900.md'.
```

The location points at the offending key of `hardslice.json` when the file could be read.

## Bad example

```csharp
// src/MyApp.Domain/IEntity.cs, moved to another namespace: 'MyApp.Domain.IEntity' no longer exists.
namespace MyApp.Domain.Common;

public interface IEntity;
```

## Good example

```csharp
// src/MyApp.Domain/IEntity.cs: the contract stays where hardslice.json declares it.
namespace MyApp.Domain;

public interface IEntity;

// src/MyApp.Domain/IAggregateRoot.cs: an aggregate root is an entity.
public interface IAggregateRoot : IEntity
{
    IReadOnlyList<IDomainEvent> DequeueDomainEvents();
}
```

## How to fix

1. Restore the contract types `IEntity`, `IAggregateRoot` and `IDomainEvent` in `src/MyApp.Domain/`, and `ICommand<T>`, `IQuery<T>` and `IRequestHandler<TRequest, TResponse>` in `src/MyApp/Shared/Messaging/`, with their namespaces.
2. Restore `hardslice.json` from version control. When it declares a version that the analyzers do not read, update `HardSlice.Analyzers` and `hardslice.tool` instead: a maintainer decision, since both files are protected.
3. Run the check script again.

Moving or renaming a contract changes the architecture of the application: it requires a maintainer decision, who then updates `hardslice.json` in the same change.

## Skill

The message names the `fix-architecture-violation` skill, in `.claude/skills/` and `.agents/skills/`: it reads the diagnostic and this sheet, applies the first fix above that matches, runs the check script again, and stops to explain the conflict when only a workaround would make it pass.

## Forbidden workarounds

These mechanisms are not valid fixes for HS900. Do not use them to make the build pass:

- `#pragma warning disable HS900`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, or `dotnet_diagnostic.HS900.severity` in `.editorconfig` or `.globalconfig`.
- Editing `hardslice.json` so that it names other types than the contracts of the application, or removing a key.
- Turning off the rules that need the contracts (`dotnet_diagnostic.HS901.severity = none`, and so on) so that HS900 stays silent.
- Declaring an empty lookalike type with the name `hardslice.json` expects, in another namespace or project, while the code uses another contract.
- Removing, editing or downgrading the HardSlice analyzer or its package reference.

## What the rule does not detect

- A contract declared in a project that no compilation of the solution references, outside the project of the slices: it is never required there, so never checked.
- `style` and `shared` of `hardslice.json`: the architecture tests validate them (HS017).

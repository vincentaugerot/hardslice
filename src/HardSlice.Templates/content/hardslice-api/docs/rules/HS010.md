# HS010: the domain and the slices never read the system clock

Severity: error. Reported at build time by `HardSlice.Analyzers`, in every analysis mode, in the domain and in the slices. Not reported in test projects.

## Rule

The current instant comes from a `TimeProvider` that the handler receives, never from the system clock. HS010 reports a read of these properties, recognized by their symbols in the base class library:

| Property | Replaced by, on an injected `TimeProvider` |
|---|---|
| `DateTimeOffset.UtcNow` | `GetUtcNow()` |
| `DateTimeOffset.Now` | `GetLocalNow()` |
| `DateTime.UtcNow` | `GetUtcNow().UtcDateTime` |
| `DateTime.Now` | `GetLocalNow().DateTime` |
| `DateTime.Today` | `GetLocalNow().Date` |

A read through `using static System.DateTime;`, in a field or property initializer, or in a lambda converted to an expression tree, such as the filter of an EF Core query, is reported too. `nameof(DateTime.Now)` is not a read.

A slice also never waits on the system clock. HS010 reports there every overload of these methods that takes no `TimeProvider`, recognized by their symbols too:

| Call | Replaced by, with the injected `TimeProvider` |
|---|---|
| `Task.Delay(TimeSpan)`, `Task.Delay(int)`, with or without a `CancellationToken` | `Task.Delay(delay, timeProvider, cancellationToken)` |
| `new PeriodicTimer(TimeSpan)` | `new PeriodicTimer(period, timeProvider)`, or `AddRecurringCommand` for a command sent at regular intervals |

The rule covers two places:

- the domain: every type of the project that declares the entity contract of `hardslice.json` (`IEntity`, in `MyApp.Domain`), reported in the build of that project;
- the slices: the code in a namespace `MyApp.Features.<Module>.<Slice>` and below it.

## Why

A rule that depends on the current instant, such as "a booking starts in the future" or "a cancellation is late within 24 hours of the start", is tested by choosing that instant. When the domain or a handler reads the system clock, its tests depend on the day and the hour they run: they cannot reach the edge of the rule, and they fail at midnight, at a change of daylight saving time or on a machine in another time zone. A `TimeProvider` received by the handler makes the instant an input: tests pass a `FakeTimeProvider` (package `Microsoft.Extensions.TimeProvider.Testing`, which the unit and integration test projects reference), set to the instant of their choice and advanced with `Advance` for a delay or a timer.

A timer or a delay on the system clock makes a test wait for real: a slice that retries after a minute, or a hosted service that runs every hour, cannot be tested at all. On the injected `TimeProvider`, the test advances its `FakeTimeProvider` and the timer fires at once.

The domain stays deterministic: it receives the instant as a parameter of its methods, and only the handler, which already receives its dependencies, reads it once per request.

## Diagnostic

```text
HS010: 'ConfirmBookingHandler.Handle' in slice 'Bookings/ConfirmBooking' reads 'DateTimeOffset.UtcNow'. The domain and the slices never read the system clock. Fix: inject TimeProvider and call GetUtcNow(), or pass the instant to the domain as a parameter. Skill: fix-architecture-violation. Doc: 'docs/rules/HS010.md'.
```

The diagnostic names the member the read is in, its slice or the domain project, and the property; the fix names the call of `TimeProvider` that replaces it. In the domain, and in an expression tree, the fix is adapted, and a timer names the overload that takes `TimeProvider`:

```text
HS010: 'Booking.Confirm' in domain project 'MyApp.Domain' reads 'DateTimeOffset.UtcNow'. ... Fix: take the instant as a parameter; the handler reads it from an injected TimeProvider with GetUtcNow(). ...
HS010: 'ListUpcomingBookingsHandler.Handle' in slice 'Bookings/ListUpcomingBookings' reads 'DateTimeOffset.UtcNow'. ... Fix: read the instant once before the query, from an injected TimeProvider with GetUtcNow(), and use that variable in the expression. ...
HS010: 'FeedListener.ExecuteAsync' in slice 'Feeds/ImportFeed' waits on the system clock with 'Task.Delay(TimeSpan, CancellationToken)'. A slice waits on an injected TimeProvider, which tests advance. Fix: inject TimeProvider and pass it: Task.Delay(delay, timeProvider, cancellationToken). Skill: fix-architecture-violation. Doc: 'docs/rules/HS010.md'.
```

## Bad example

```csharp
// src/MyApp.Domain/Bookings/Booking.cs
public static Booking Confirm(Guid roomId, BookingPeriod period, IEnumerable<Booking> existingBookings)
{
    if (period.Start < DateTimeOffset.UtcNow)
        throw new BookingInThePastException(period);
    // ...
}

// src/MyApp/Features/Bookings/ListUpcomingBookings/ListUpcomingBookings.cs
public async Task<IReadOnlyList<Guid>> Handle(ListUpcomingBookingsQuery query, CancellationToken cancellationToken) =>
    await db.Set<Booking>().AsNoTracking()
        .Where(booking => booking.Period.Start > DateTimeOffset.UtcNow)
        .Select(booking => booking.Id.Value)
        .ToListAsync(cancellationToken);
```

## Good example

```csharp
// src/MyApp.Domain/Bookings/Booking.cs
public static Booking Confirm(Guid roomId, BookingPeriod period, IEnumerable<Booking> existingBookings, DateTimeOffset now)
{
    if (period.Start < now)
        throw new BookingInThePastException(period);
    // ...
}

// src/MyApp/Features/Bookings/ConfirmBooking/ConfirmBooking.cs
internal sealed class ConfirmBookingHandler(AppDbContext db, TimeProvider timeProvider) : IRequestHandler<ConfirmBookingCommand, Guid>
{
    public async Task<Guid> Handle(ConfirmBookingCommand command, CancellationToken cancellationToken)
    {
        // ...
        var booking = Booking.Confirm(command.RoomId, period, existingBookings, timeProvider.GetUtcNow());
        // ...
    }
}

// src/MyApp/Features/Bookings/ListUpcomingBookings/ListUpcomingBookings.cs
public async Task<IReadOnlyList<Guid>> Handle(ListUpcomingBookingsQuery query, CancellationToken cancellationToken)
{
    var now = timeProvider.GetUtcNow();
    return await db.Set<Booking>().AsNoTracking()
        .Where(booking => booking.Period.Start > now)
        .Select(booking => booking.Id.Value)
        .ToListAsync(cancellationToken);
}
```

## How to fix

1. In a handler: add a `TimeProvider` parameter to its constructor and replace the property with the call of the table above. `Program.cs` registers `TimeProvider.System`; keep that registration.
2. In the domain: add a `DateTimeOffset now` parameter to the method that needs the instant, and pass `timeProvider.GetUtcNow()` from the handler that calls it. The domain never receives `TimeProvider` itself: an instant is enough, and a method that takes it is tested without any fake.
3. In an expression tree, such as the filter of a query: read the instant once, before the query, into a local variable, and use the variable in the expression. EF Core sends it to the database as a parameter, the same for every row.
4. A delay or a timer: pass the injected `TimeProvider` to the overload that takes it, `Task.Delay(delay, timeProvider, cancellationToken)` or `new PeriodicTimer(period, timeProvider)`. A command sent at regular intervals needs no timer of its own: register it with `services.AddRecurringCommand<TCommand, TResponse>(section, interval)` in its module, as `dotnet new hardslice-command --every <interval>` prints.
5. In tests: pass the instant directly to the domain, and give the handler a `FakeTimeProvider` set to the instant the case needs, advanced with `Advance` past a delay or a period. `RecurringCommandCycles` of the integration tests does it for a recurring command.
6. Run the check script again.

## Skill

The message names the `fix-architecture-violation` skill, in `.claude/skills/` and `.agents/skills/`: it reads the diagnostic and this sheet, applies the first fix above that matches, runs the check script again, and stops to explain the conflict when only a workaround would make it pass.

## Forbidden workarounds

These mechanisms are not valid fixes for HS010. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS010`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, or `dotnet_diagnostic.HS010.severity` in `.editorconfig` or `.globalconfig`.
- Moving the read into a static helper of `Shared`, of the module or of another project that the slice or the domain calls, such as `Clock.UtcNow`, only because HS010 does not follow calls. The code still depends on the system clock.
- Reading `TimeProvider.System.GetUtcNow()` directly instead of the injected `TimeProvider`: the rule does not report it, but tests can no longer choose the instant.
- Passing `TimeProvider.System` to `Task.Delay` or `PeriodicTimer` instead of the injected `TimeProvider`, or waiting with `System.Threading.Timer`, `Thread.Sleep` or a loop that polls, only because the rule does not report them: tests wait for real again.
- Reading the clock through another API only to escape the rule: `Stopwatch`, `Environment.TickCount`, `DateTime.Now` reached by reflection or `dynamic`, a default value computed by the database and read back by the domain.
- Moving a slice or domain type out of its namespace, or adding an auto-generated header, only to hide it from the rule.

## What the rule does not detect

- The code of the module outside its slices (`<Module>Module`, the EF Core configurations), `Shared`, `Program.cs` and the other projects. A read moved into a helper they declare and that a slice calls is not detected: it is a forbidden workaround.
- A read in a method of another assembly that the code calls: the methods it calls are not followed.
- `TimeProvider.System`, `Stopwatch`, `Environment.TickCount` and the other ways to measure time.
- The other waits on the system clock, such as `System.Threading.Timer`, `Thread.Sleep`, `CancellationTokenSource.CancelAfter` or `Task.WaitAsync(TimeSpan)`, and a timer or a delay in the domain or outside the slices, such as `Shared`.
- The domain when `hardslice.json` or its entity contract is unusable: HS900 reports the configuration instead.
- Test projects, which choose their instant themselves.

# HS901: a type has one role

Severity: error. Reported at build time by `HardSlice.Analyzers`, on the declaration of the type, in the project that declares it. Not reported in test projects.

## Rule

A type plays one role. It is never classified in two incompatible categories:

| Implements | Categories |
|---|---|
| `IEntity` or `IAggregateRoot`, and `IDomainEvent` | entity and domain event |
| `ICommand<T>` and `IQuery<T>` | command and query |
| `IEntity` or `IAggregateRoot`, and `ICommand<T>` or `IQuery<T>` | entity and request |

Categories come from the contracts of `hardslice.json` only, implemented directly or through a base class or a derived interface (HS900).

## Why

Each rule checks a type through its role: an entity keeps its state private (HS007), a domain event is a `record` (HS009), a query never writes (HS006). A type with two roles would follow two contradictory sets of rules, and its readers could not tell what it is.

## Diagnostic

```text
HS901: 'BookingSnapshot' is both an entity and a domain event: it implements 'IAggregateRoot' and 'IDomainEvent'. A type is either an entity, which has an identity and changes through its methods, or a domain event, an immutable fact an entity records. Fix: keep 'BookingSnapshot' as the entity and declare the event as a separate record that it records. Skill: fix-architecture-violation. Doc: 'docs/rules/HS901.md'.
```

## Bad example

```csharp
// The booking is published as its own event.
public sealed class Booking : IAggregateRoot, IDomainEvent { /* ... */ }

// One request for both changing and reading a booking.
public sealed record ConfirmOrGetBooking(Guid BookingId) : ICommand<BookingDto>, IQuery<BookingDto>;
```

## Good example

```csharp
// The aggregate records a separate, immutable event.
public sealed class Booking : IAggregateRoot { /* ... */ }

public sealed record BookingConfirmed(BookingId BookingId, Guid RoomId, BookingPeriod Period) : IDomainEvent;

// One slice per use case: a command that changes state, a query that reads.
public sealed record ConfirmBookingCommand(Guid RoomId, DateTimeOffset Start, DateTimeOffset End) : ICommand<Guid>;

public sealed record GetBookingQuery(Guid BookingId) : IQuery<BookingDto?>;
```

## How to fix

1. **Entity and domain event**: keep the entity, and add a `record` implementing `IDomainEvent` that carries the facts other code reacts to. The entity records it in its `DomainEvents`.
2. **Command and query**: split the request into a command in one slice and a query in another. A command may return an identifier; reading the result is the query's job.
3. **Entity and request**: declare the request as its own `record` in its slice, carrying the values the entity needs. The handler loads the entity and calls its methods.

Then run the check script again.

## Skill

The message names the `fix-architecture-violation` skill, in `.claude/skills/` and `.agents/skills/`: it reads the diagnostic and this sheet, applies the first fix above that matches, runs the check script again, and stops to explain the conflict when only a workaround would make it pass.

## Forbidden workarounds

These mechanisms are not valid fixes for HS901. Do not use them to make the build pass:

- `#pragma warning disable HS901`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, or `dotnet_diagnostic.HS901.severity` in `.editorconfig` or `.globalconfig`.
- Implementing `IRequest<T>` directly, or a homonymous interface of another namespace, instead of `ICommand<T>` or `IQuery<T>`, so that one of the two roles disappears from the classification.
- Removing `IEntity` from a type that has an identity only to declare it as an event or a request.
- Editing `hardslice.json` so that a contract designates another type.

## What the rule does not detect

- A type whose role differs from its contract, such as an entity that implements no contract: classification relies on contracts only, never on names or an `Id` property. HS902 covers the entities EF Core maps.
- A request handler that is also a command or a query: handlers are classified by `IRequestHandler<,>`, which no rule combines with another category yet.

# HS006: a query handler, a hosted service or a condition of a slice reads without tracking and never writes

Severity: error. Reported at build time by `HardSlice.Analyzers`, in the `Recommended` and `All` analysis modes. Not reported in test projects.

## Rule

A query handler implements `IRequestHandler<TQuery, TResponse>`, directly or through a base class, for a request that implements `IQuery<TResponse>`. All its code is examined: its methods, constructors, lambdas, local functions, field and property initializers, and the types nested in it.

Two other entry points of a slice run outside the mediator, its pipeline and its transaction, and follow the same rule. Each is declared in the namespace of a slice, `MyApp.Features.<Module>.<Slice>` or below, and recognized by the interface it implements, never by its name:

- **A hosted service**: a class that implements `IHostedService`, directly or through `BackgroundService`, such as a service that consumes a queue and sends a command for each message. Its work is the command it sends through `IMediator`, whose handler writes in the transaction of `TransactionBehavior`.
- **A condition of a recurring command**: a class that implements `IRecurringCommandCondition<TCommand>`, the interface of `Shared/Messaging` declared beside `IRequestHandler<TRequest, TResponse>`, which decides before each send whether the command goes. Its work is to decide: the command does the rest.

All their code is examined, as for a query handler. The hosted services of `Shared`, such as `RecurringCommandService<TCommand, TResponse>`, and those declared in the namespace of a module outside its slices, are not.

A query handler, a hosted service or a condition of a slice never writes, never turns tracking back on, and gives a **local guarantee** that what it reads is not tracked. HS006 reports:

1. **A write through EF Core**: `SaveChanges`, `SaveChangesAsync`, `ExecuteUpdate`, `ExecuteUpdateAsync`, `ExecuteDelete`, `ExecuteDeleteAsync`, `ExecuteSql`, `ExecuteSqlAsync`, `ExecuteSqlRaw`, `ExecuteSqlRawAsync`, `ExecuteSqlInterpolated`, `ExecuteSqlInterpolatedAsync`, or a change of what the context tracks: `Add`, `AddAsync`, `AddRange`, `AddRangeAsync`, `Attach`, `AttachRange`, `Update`, `UpdateRange`, `Remove`, `RemoveRange` of a `DbContext` or a `DbSet<T>`.
2. **Tracking turned back on or reconfigured**: `AsTracking()`, or an assignment of `ChangeTracker.QueryTrackingBehavior`, whatever its value.
3. **A read that always tracks**: `Find` and `FindAsync`.
4. **A read without a local guarantee**: a query rooted in a set of entities, whose result holds an entity, and whose guaranteed chain holds neither `AsNoTracking()` nor `AsNoTrackingWithIdentityResolution()`.

HS006 recognizes a query when:

- it starts from a `DbSet<T>` property, `Set<T>()`, `FromSql`, `FromSqlRaw` or `FromSqlInterpolated`, where `T` is an entity (`IEntity` or `IAggregateRoot`);
- it chains LINQ and EF Core operators in one expression, or goes through a local `IQueryable<T>` of the same method, initialized by a recognized query and reassigned only as `query = query.<operators>`, conditionally or not;
- it goes through a composition: a method that is not an operator, returns an `IQueryable<T>` and receives the queries it composes as arguments, such as a rule of the domain (see [A rule of the domain in a query](#a-rule-of-the-domain-in-a-query)). Its body is not read. Each query it receives must be recognized, and the composed query is guaranteed when each of them is: otherwise the first one without a guarantee is reported as its root;
- it runs: `ToList`, `ToArray`, `ToDictionary`, `ToHashSet`, `ToLookup`, `First`, `Single`, `Last`, `ElementAt` and their `OrDefault` and `Async` variants, `Load`, `ForEachAsync`, `AsEnumerable`, `AsAsyncEnumerable`, or a `foreach` or `await foreach` on the query.

The **guaranteed chain** is the expression that runs the query and, for a local, its initializer. A reassignment may not run: the rule does not follow the control flow. An `AsNoTracking()` added by a reassignment therefore guarantees nothing, while an `AsTracking()` added by a reassignment is still reported.

The **result holds an entity** when the elements the query returns hold one (the entity itself, a collection of entities, an anonymous type or a DTO with an entity member, as HS005 follows them), or when the last projection passes an expression that holds an entity into its result: a member of an anonymous type, an argument of a constructor, a value of an object initializer, or an argument or the target of a method that EF Core evaluates on the client, such as `Select(booking => Describe(booking))`. To call that method, EF Core materializes the entity, and tracks it.

A query whose result holds no entity is compliant without `AsNoTracking()`: `Select(booking => booking.Id)` or a DTO of scalars track nothing. The global `UseQueryTrackingBehavior` of the context is not read: it lives in the composition root and can change without the handler changing.

## Why

A query answers without changing state. Its handler runs outside the transaction of the commands, often in parallel with them, on a context that other components of the same scope may share.

A hosted service or a condition that writes does it outside the transaction, the validation and the logs of a command, and the integration tests of its slice, which send the command, never see it. One that reads with tracking leaves entities attached to a context that it may share with what it resolves next in the same scope. Reading with `AsNoTracking()` is all it needs to decide, such as whether a version of a schedule already covers the day, and the command it sends or lets go does the work.

A tracked read is a hidden write path: the entity stays attached to the context, a later `SaveChanges` in the same scope saves any change made to it, and its snapshot costs memory and time on every read. `Find` returns an entity the context already tracks, possibly modified and unsaved. Turning tracking back on, or changing `QueryTrackingBehavior`, changes the context for every component that receives it after the handler. A write in a query handler escapes the transaction, the validation and the tests of the commands.

`AsNoTracking()` in the handler states the guarantee where the read happens. The global setting of the context does not: it can change in `Program.cs` without the handler changing, and HS006 could not prove it.

## Diagnostic

```text
HS006: query handler 'GetBookingHandler' reads 'Booking' from 'Set<Booking>()' without a local guarantee that it is not tracked. Query handlers read without tracking and never write. Fix: add AsNoTracking() where the query starts, and project to a DTO. Skill: fix-architecture-violation. Doc: 'docs/rules/HS006.md'.
```

The diagnostic is reported on the call that runs the query, the write, `AsTracking`, `Find` or the assignment, or on the collection of a `foreach`. It names the handler, the hosted service or the condition, with its slice, and what it does; for a read, the entity and the root of the query. The other forms read:

## Bad example

```csharp
// src/MyApp/Features/Bookings/GetBooking/GetBooking.cs
internal sealed class GetBookingHandler(AppDbContext db) : IRequestHandler<GetBookingQuery, BookingDto?>
{
    public Task<BookingDto?> Handle(GetBookingQuery query, CancellationToken cancellationToken)
    {
        var id = new BookingId(query.BookingId);
        // ToDto runs on the client: EF Core materializes the booking and tracks it.
        return db.Set<Booking>()
            .Where(booking => booking.Id == id)
            .Select(booking => ToDto(booking))
            .SingleOrDefaultAsync(cancellationToken);
    }

    private static BookingDto ToDto(Booking booking) =>
        new(booking.Id.Value, booking.RoomId, booking.Period.Start, booking.Period.End, booking.Status.ToString());
}

// AsNoTracking added on one path only: the other one tracks.
IQueryable<Booking> bookings = db.Set<Booking>();
if (query.ReadOnly)
    bookings = bookings.AsNoTracking();
return await bookings.ToListAsync(cancellationToken);
```

A hosted service and a condition of a slice that write and track:

```csharp
// src/MyApp/Features/Feeds/ImportFeed/FeedListener.cs
internal sealed class FeedListener(IServiceScopeFactory scopes, FeedQueue queue) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        await foreach (var message in queue.ReadAllAsync(stoppingToken))
        {
            await using var scope = scopes.CreateAsyncScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            // Written outside the mediator: no validation, no transaction, no handler to test.
            db.Set<Feed>().Add(Feed.From(message));
            await db.SaveChangesAsync(stoppingToken);
        }
    }
}

// src/MyApp/Features/Schedule/ImportSchedule/ImportScheduleCondition.cs
internal sealed class ImportScheduleCondition(AppDbContext db, TimeProvider clock) : IRecurringCommandCondition<ImportScheduleCommand>
{
    public async Task<string?> CheckAsync(RecurringCycle cycle, CancellationToken cancellationToken)
    {
        // Tracked: the versions stay attached to the context of the scope.
        var versions = await db.Set<ScheduleVersion>().ToListAsync(cancellationToken);
        return versions.Any(version => version.CoversDay(DateOnly.FromDateTime(clock.GetUtcNow().Date))) ? "a version covers the day" : null;
    }
}
```

## Good example

```csharp
// src/MyApp/Features/Bookings/GetBooking/GetBooking.cs
internal sealed class GetBookingHandler(AppDbContext db) : IRequestHandler<GetBookingQuery, BookingDto?>
{
    public Task<BookingDto?> Handle(GetBookingQuery query, CancellationToken cancellationToken)
    {
        var id = new BookingId(query.BookingId);
        return db.Set<Booking>()
            .AsNoTracking()
            .Where(booking => booking.Id == id)
            .Select(booking => new BookingDto(
                booking.Id.Value, booking.RoomId, booking.Period.Start, booking.Period.End, booking.Status.ToString()))
            .SingleOrDefaultAsync(cancellationToken);
    }
}

// A filter added conditionally on a query that starts without tracking.
var bookings = db.Set<Booking>().AsNoTracking();
if (query.RoomId is { } roomId)
    bookings = bookings.Where(booking => booking.RoomId == roomId);
```

A hosted service that sends a command for each message, and a condition that reads without tracking:

```csharp
// src/MyApp/Features/Feeds/ImportFeed/FeedListener.cs
internal sealed class FeedListener(IServiceScopeFactory scopes, FeedQueue queue, ILogger<FeedListener> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        await foreach (var message in queue.ReadAllAsync(stoppingToken))
        {
            try
            {
                await using var scope = scopes.CreateAsyncScope();
                await scope.ServiceProvider.GetRequiredService<IMediator>().Send(new ImportFeedCommand(message.Id), stoppingToken);
            }
            catch (Exception exception) when (!stoppingToken.IsCancellationRequested)
            {
                logger.LogError(exception, "Feed message {MessageId} could not be imported", message.Id);
            }
        }
    }
}

// src/MyApp/Features/Schedule/ImportSchedule/ImportScheduleCondition.cs: only the cycle at start is held back.
internal sealed class ImportScheduleCondition(AppDbContext db, TimeProvider clock) : IRecurringCommandCondition<ImportScheduleCommand>
{
    public async Task<string?> CheckAsync(RecurringCycle cycle, CancellationToken cancellationToken)
    {
        if (!cycle.AtStart)
            return null;

        var day = DateOnly.FromDateTime(clock.GetUtcNow().Date);
        return await ScheduleVersion.InForceOn(db.Set<ScheduleVersion>().AsNoTracking(), day).AnyAsync(cancellationToken)
            ? $"a version of the schedule covers {day}"
            : null;
    }
}
```

## A rule of the domain in a query

Some business rules must run in the database, inside a query: the bookings that overlap a period, the services that run on a date, the version of a schedule in force on it. Such a rule belongs to the domain, next to its aggregate, unit tested on lists, and a query uses it in one of two legitimate forms:

- **A predicate**, an `Expression<Func<T, bool>>` of the domain that the handler passes to `Where`, `Any` or `Count`. It is an argument of an operator: the query keeps its root and its chain in the handler, and HS006 analyzes it as any other.
- **A composition**, a static method from `IQueryable<T>` to `IQueryable<TResult>` that receives every query it composes as a parameter and only adds operators to them. The handler gives it its sources, each one started with `AsNoTracking()`, and projects the result to values or a DTO of values. HS006 follows the composition through the queries the handler passes to it: it reports the composed query when the result holds an entity and one of these queries has no `AsNoTracking()`, as it reports the same chain written in the handler.

```csharp
// src/MyApp.Domain/Bookings/Booking.cs: the domain never references EF Core.
public static Expression<Func<Booking, bool>> IsConfirmed { get; } = booking => booking.Status == BookingStatus.Confirmed;

public static IQueryable<Booking> Overlapping(IQueryable<Booking> bookings, BookingPeriod period) =>
    bookings.Where(booking => booking.Period.Start < period.End && booking.Period.End > period.Start);

// src/MyApp/Features/Bookings/ListOccupiedRooms/ListOccupiedRooms.cs: the handler gives the source and projects.
var rooms = await Booking.Overlapping(db.Set<Booking>().AsNoTracking(), period)
    .Where(Booking.IsConfirmed)
    .Select(booking => booking.RoomId)
    .Distinct()
    .ToListAsync(cancellationToken);
```

A unit test of the domain calls the composition on a list: `Booking.Overlapping(bookings.AsQueryable(), period)`.

The **forbidden form** is a helper that creates its source itself, from a context or a set it receives or reaches, or that returns entities already read, such as a `Task<List<Booking>>`. It moves the read out of the handler, where HS006 does not look: HS006 neither follows nor reports it, and the read loses its local guarantee. Writing one to make the build pass is a [forbidden workaround](#forbidden-workarounds).

## How to fix

1. A write belongs to a command: move it into a command slice, whose handler runs in the transaction of `TransactionBehavior`. A query handler that must record something, such as an audit of the read, sends a command or publishes an event instead. A hosted service creates the command and sends it through `IMediator` in a scope of its own, and its handler writes. A condition only decides: the write goes into the handler of the command it lets go.
2. Start every query on an entity with `AsNoTracking()`, right after its root (`db.Set<Booking>()` or the `DbSet<T>` property), in the expression that runs it, in the initializer of its local, or in each query passed to a rule of the domain. Use `AsNoTrackingWithIdentityResolution()` when the result must share one instance per entity.
3. Project to a DTO inside `Select`, with a constructor or an initializer that takes values only: EF Core translates it to SQL and never materializes the entity. Move a mapping method that takes the entity into the projection itself. A hosted service or a condition projects to the values it needs, or asks `AnyAsync` or `CountAsync`.
4. Replace `Find` and `FindAsync` with `AsNoTracking().Where(...)` and a projection, then `SingleOrDefaultAsync`.
5. Remove `AsTracking()` and any assignment of `ChangeTracker.QueryTrackingBehavior`: a query reads without tracking, and the context belongs to its scope.
6. Run the check script again.

## Skill

The message names the `fix-architecture-violation` skill, in `.claude/skills/` and `.agents/skills/`: it reads the diagnostic and this sheet, applies the first fix above that matches, runs the check script again, and stops to explain the conflict when only a workaround would make it pass.

## Forbidden workarounds

These mechanisms are not valid fixes for HS006. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS006`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS006.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- Moving a write, or a read without a local guarantee, into a helper method, a base class, an extension method, a repository or a service outside the handler, only because HS006 does not follow the methods it calls.
- Getting the query from a field, a property, a parameter or a helper, or reassigning its local another way, only because HS006 cannot analyze those forms.
- A helper, in the domain or elsewhere, that creates the source of its query itself or returns entities, presented as a rule of the domain: a rule receives its queries from the handler and returns a query (see [A rule of the domain in a query](#a-rule-of-the-domain-in-a-query)).
- Writing through ADO.NET, Dapper, a stored procedure called through another library, or any API other than EF Core, from a query handler.
- Relying on `UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking)` in `Program.cs` instead of `AsNoTracking()` in the handler.
- Turning the query into a command, or dropping `IQuery<T>` from it, so that the rule no longer recognizes its handler.
- Moving a hosted service or a condition out of the namespace of its slice, into `Shared` or the root of its module, or replacing `BackgroundService` or `IRecurringCommandCondition<TCommand>` with a hand-written loop or check, only because HS006 examines them in a slice.
- Removing `IEntity` or `IAggregateRoot` from the entity, or changing the contracts of `hardslice.json`.

## What the rule does not detect

Forms HS006 cannot analyze. They are allowed when they respect the rule, but HS006 neither reports them nor declares them compliant:

- A query obtained from a field, a property other than a `DbSet<T>`, a parameter, or a method that is not a LINQ or EF Core operator and receives no query, such as a helper that takes the context and creates its own source; a query passed to a method whose result is not a query, which is not followed.
- The body of a composition: a composition that creates a source of its own, ignores the queries it receives or turns tracking back on is not detected. A composition that receives a query HS006 cannot analyze, such as a parameter of the handler, is not analyzed.
- A local reassigned other than as `query = query.<operators>`, declared without an initializer, or passed by `ref` or `out`.
- A compiled query (`EF.CompileQuery`, `EF.CompileAsyncQuery`).
- A write made in a helper, through ADO.NET or another library, or through `Entry(entity).State`.
- A query whose root is not an entity, such as a keyless read model, or an entity that does not implement `IEntity` or `IAggregateRoot`.
- An entity that reaches the result through a conditional expression, a string interpolation or a type known only at runtime.
- The global `UseQueryTrackingBehavior`, whatever its value: only the local guarantee counts.
- A hosted service or a condition declared outside the namespace of a slice, such as the services of `Shared` or of the root of a module, a service registered with a factory lambda instead of a type, and the code a hosted service or a condition calls in another type. A condition whose interface is not declared beside the `requestHandler` contract, in `Shared/Messaging`, is not recognized.
- Handlers, hosted services and conditions when `hardslice.json` or its `entity`, `query` or `requestHandler` contract is unusable: HS900 reports the configuration instead.
- Projects that do not reference EF Core, and test projects.

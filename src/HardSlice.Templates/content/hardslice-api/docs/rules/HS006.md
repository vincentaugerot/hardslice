# HS006: a query handler reads without tracking and never writes

Severity: error. Reported at build time by `HardSlice.Analyzers`, in the `Recommended` and `All` analysis modes. Not reported in test projects.

## Rule

A query handler implements `IRequestHandler<TQuery, TResponse>`, directly or through a base class, for a request that implements `IQuery<TResponse>`. All its code is examined: its methods, constructors, lambdas, local functions, field and property initializers, and the types nested in it.

A query handler never writes, never turns tracking back on, and gives a **local guarantee** that what it reads is not tracked. HS006 reports:

1. **A write through EF Core**: `SaveChanges`, `SaveChangesAsync`, `ExecuteUpdate`, `ExecuteUpdateAsync`, `ExecuteDelete`, `ExecuteDeleteAsync`, `ExecuteSql`, `ExecuteSqlAsync`, `ExecuteSqlRaw`, `ExecuteSqlRawAsync`, `ExecuteSqlInterpolated`, `ExecuteSqlInterpolatedAsync`, or a change of what the context tracks: `Add`, `AddAsync`, `AddRange`, `AddRangeAsync`, `Attach`, `AttachRange`, `Update`, `UpdateRange`, `Remove`, `RemoveRange` of a `DbContext` or a `DbSet<T>`.
2. **Tracking turned back on or reconfigured**: `AsTracking()`, or an assignment of `ChangeTracker.QueryTrackingBehavior`, whatever its value.
3. **A read that always tracks**: `Find` and `FindAsync`.
4. **A read without a local guarantee**: a query rooted in a set of entities, whose result holds an entity, and whose guaranteed chain holds neither `AsNoTracking()` nor `AsNoTrackingWithIdentityResolution()`.

HS006 recognizes a query when:

- it starts from a `DbSet<T>` property, `Set<T>()`, `FromSql`, `FromSqlRaw` or `FromSqlInterpolated`, where `T` is an entity (`IEntity` or `IAggregateRoot`);
- it chains LINQ and EF Core operators in one expression, or goes through a local `IQueryable<T>` of the same method, initialized by a recognized query and reassigned only as `query = query.<operators>`, conditionally or not;
- it runs: `ToList`, `ToArray`, `ToDictionary`, `ToHashSet`, `ToLookup`, `First`, `Single`, `Last`, `ElementAt` and their `OrDefault` and `Async` variants, `Load`, `ForEachAsync`, `AsEnumerable`, `AsAsyncEnumerable`, or a `foreach` or `await foreach` on the query.

The **guaranteed chain** is the expression that runs the query and, for a local, its initializer. A reassignment may not run: the rule does not follow the control flow. An `AsNoTracking()` added by a reassignment therefore guarantees nothing, while an `AsTracking()` added by a reassignment is still reported.

The **result holds an entity** when the elements the query returns hold one (the entity itself, a collection of entities, an anonymous type or a DTO with an entity member, as HS005 follows them), or when the last projection passes an expression that holds an entity into its result: a member of an anonymous type, an argument of a constructor, a value of an object initializer, or an argument or the target of a method that EF Core evaluates on the client, such as `Select(booking => Describe(booking))`. To call that method, EF Core materializes the entity, and tracks it.

A query whose result holds no entity is compliant without `AsNoTracking()`: `Select(booking => booking.Id)` or a DTO of scalars track nothing. The global `UseQueryTrackingBehavior` of the context is not read: it lives in the composition root and can change without the handler changing.

## Why

A query answers without changing state. Its handler runs outside the transaction of the commands, often in parallel with them, on a context that other components of the same scope may share.

A tracked read is a hidden write path: the entity stays attached to the context, a later `SaveChanges` in the same scope saves any change made to it, and its snapshot costs memory and time on every read. `Find` returns an entity the context already tracks, possibly modified and unsaved. Turning tracking back on, or changing `QueryTrackingBehavior`, changes the context for every component that receives it after the handler. A write in a query handler escapes the transaction, the validation and the tests of the commands.

`AsNoTracking()` in the handler states the guarantee where the read happens. The global setting of the context does not: it can change in `Program.cs` without the handler changing, and HS006 could not prove it.

## Diagnostic

```text
HS006: query handler 'GetBookingHandler' reads 'Booking' from 'Set<Booking>()' without a local guarantee that it is not tracked. Query handlers read without tracking and never write. Fix: add AsNoTracking() where the query starts, and project to a DTO. Doc: 'docs/rules/HS006.md'.
```

The diagnostic is reported on the call that runs the query, the write, `AsTracking`, `Find` or the assignment, or on the collection of a `foreach`. It names the handler and what it does; for a read, the entity and the root of the query. The other forms read:

```text
HS006: query handler 'ListBookingsHandler' writes through 'ExecuteDeleteAsync'. Query handlers read without tracking and never write. Fix: move the write into a command slice. Doc: 'docs/rules/HS006.md'.
HS006: query handler 'ListBookingsHandler' turns tracking back on with 'AsTracking'. ... Fix: remove AsTracking(): the query starts with AsNoTracking(). ...
HS006: query handler 'ListBookingsHandler' reconfigures tracking through 'ChangeTracker.QueryTrackingBehavior'. ... Fix: remove the assignment, which changes the context for every component of the scope, and start each query with AsNoTracking(). ...
HS006: query handler 'GetBookingHandler' reads with 'FindAsync', which always tracks the entity it returns. ... Fix: query the entity with AsNoTracking() and Where(), and project to a DTO. ...
```

## Bad example

```csharp
// src/MyApp/Features/Bookings/GetBooking/GetBooking.cs
internal sealed class GetBookingHandler(AppDbContext db) : IRequestHandler<GetBookingQuery, BookingDto?>
{
    public Task<BookingDto?> Handle(GetBookingQuery query, CancellationToken cancellationToken)
    {
        var id = new BookingId(query.BookingId);
        // ToDto runs on the client: EF Core materializes the booking and tracks it.
        return db.Set<Booking>()
            .Where(booking => booking.Id == id)
            .Select(booking => ToDto(booking))
            .SingleOrDefaultAsync(cancellationToken);
    }

    private static BookingDto ToDto(Booking booking) =>
        new(booking.Id.Value, booking.RoomId, booking.Period.Start, booking.Period.End, booking.Status.ToString());
}

// AsNoTracking added on one path only: the other one tracks.
IQueryable<Booking> bookings = db.Set<Booking>();
if (query.ReadOnly)
    bookings = bookings.AsNoTracking();
return await bookings.ToListAsync(cancellationToken);
```

## Good example

```csharp
// src/MyApp/Features/Bookings/GetBooking/GetBooking.cs
internal sealed class GetBookingHandler(AppDbContext db) : IRequestHandler<GetBookingQuery, BookingDto?>
{
    public Task<BookingDto?> Handle(GetBookingQuery query, CancellationToken cancellationToken)
    {
        var id = new BookingId(query.BookingId);
        return db.Set<Booking>()
            .AsNoTracking()
            .Where(booking => booking.Id == id)
            .Select(booking => new BookingDto(
                booking.Id.Value, booking.RoomId, booking.Period.Start, booking.Period.End, booking.Status.ToString()))
            .SingleOrDefaultAsync(cancellationToken);
    }
}

// A filter added conditionally on a query that starts without tracking.
var bookings = db.Set<Booking>().AsNoTracking();
if (query.RoomId is { } roomId)
    bookings = bookings.Where(booking => booking.RoomId == roomId);
```

## How to fix

1. A write belongs to a command: move it into a command slice, whose handler runs in the transaction of `TransactionBehavior`. A query handler that must record something, such as an audit of the read, sends a command or publishes an event instead.
2. Start every query on an entity with `AsNoTracking()`, right after its root (`db.Set<Booking>()` or the `DbSet<T>` property), in the expression that runs it or in the initializer of its local. Use `AsNoTrackingWithIdentityResolution()` when the result must share one instance per entity.
3. Project to a DTO inside `Select`, with a constructor or an initializer that takes values only: EF Core translates it to SQL and never materializes the entity. Move a mapping method that takes the entity into the projection itself.
4. Replace `Find` and `FindAsync` with `AsNoTracking().Where(...)` and a projection, then `SingleOrDefaultAsync`.
5. Remove `AsTracking()` and any assignment of `ChangeTracker.QueryTrackingBehavior`: a query reads without tracking, and the context belongs to its scope.
6. Run the check script again.

## Forbidden workarounds

These mechanisms are not valid fixes for HS006. Do not use them to make the build pass. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS006`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, `dotnet_diagnostic.HS006.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- Moving a write, or a read without a local guarantee, into a helper method, a base class, an extension method, a repository or a service outside the handler, only because HS006 does not follow the methods it calls.
- Getting the query from a field, a property, a parameter or a helper, or reassigning its local another way, only because HS006 cannot analyze those forms.
- Writing through ADO.NET, Dapper, a stored procedure called through another library, or any API other than EF Core, from a query handler.
- Relying on `UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking)` in `Program.cs` instead of `AsNoTracking()` in the handler.
- Turning the query into a command, or dropping `IQuery<T>` from it, so that the rule no longer recognizes its handler.
- Removing `IEntity` or `IAggregateRoot` from the entity, or changing the contracts of `hardslice.json`.

## What the rule does not detect

Forms HS006 cannot analyze. They are allowed when they respect the rule, but HS006 neither reports them nor declares them compliant:

- A query obtained from a field, a property other than a `DbSet<T>`, a parameter or a method that is not a LINQ or EF Core operator; a query or a context passed to such a method, which is not followed.
- A local reassigned other than as `query = query.<operators>`, declared without an initializer, or passed by `ref` or `out`.
- A compiled query (`EF.CompileQuery`, `EF.CompileAsyncQuery`).
- A write made in a helper, through ADO.NET or another library, or through `Entry(entity).State`.
- A query whose root is not an entity, such as a keyless read model, or an entity that does not implement `IEntity` or `IAggregateRoot`.
- An entity that reaches the result through a conditional expression, a string interpolation or a type known only at runtime.
- The global `UseQueryTrackingBehavior`, whatever its value: only the local guarantee counts.
- Handlers when `hardslice.json` or its `entity`, `query` or `requestHandler` contract is unusable: HS900 reports the configuration instead.
- Projects that do not reference EF Core, and test projects.

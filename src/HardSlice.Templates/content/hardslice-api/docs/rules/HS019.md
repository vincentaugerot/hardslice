# HS019: a domain event is named as a past fact

Severity: suggestion. Reported by `HardSlice.Analyzers` in the `All` analysis mode only, the mode of the template; `Minimum` and `Recommended` turn it off. It never blocks the build, even with `TreatWarningsAsErrors`: the IDE shows it, and the compiler log (`ErrorLog`) records it. Not reported in test projects.

## Rule

A domain event, a type that implements `IDomainEvent` as HS009 recognizes it, is named after the fact it records, in the past tense: `BookingConfirmed`, `BookingCancelled`, `BookingPaid`.

HS019 is a naming convention, checked on the form of the name only. The name is split into words by its capitals, `BookingConfirmed` into `Booking` and `Confirmed`, and its last word must:

- end with `ed`, whatever its case: `Confirmed`, `Cancelled`, `RECEIVED`;
- or be one of these irregular past participles, whatever its case: Arisen, Awoken, Begun, Bent, Bitten, Blown, Bought, Bound, Broadcast, Broken, Brought, Built, Burnt, Caught, Chosen, Dealt, Done, Drawn, Driven, Dug, Eaten, Fallen, Felt, Flown, Forbidden, Forgiven, Forgotten, Fought, Found, Frozen, Given, Gone, Got, Gotten, Grown, Held, Hidden, Hung, Kept, Known, Laid, Left, Lent, Lit, Lost, Made, Meant, Met, Mistaken, Overdrawn, Overpaid, Overridden, Overtaken, Paid, Prepaid, Quit, Read, Rebuilt, Redone, Remade, Repaid, Reset, Resent, Resold, Retaken, Rewritten, Ridden, Risen, Rung, Said, Seen, Sent, Set, Shaken, Shot, Shown, Shut, Slept, Sold, Sought, Spent, Split, Spoken, Spread, Spun, Stolen, Stood, Struck, Stuck, Sung, Sunk, Swept, Sworn, Taken, Taught, Thrown, Told, Torn, Undergone, Underpaid, Undertaken, Understood, Undone, Upheld, Withdrawn, Withheld, Woken, Won, Worn, Wound, Written.

A version suffix is not a word: `BookingConfirmedV2` and `BookingConfirmed2` are read as `BookingConfirmed`. An underscore separates words too. The type parameters of a generic event are not part of its name: `EntityChanged<TEntity>` passes.

An abstract event, such as a base record `BookingEvent`, and an interface deriving from `IDomainEvent` name a family of events, not a fact: they are not checked. A type that is both an entity and a domain event is reported by HS901 only.

## Why

A domain event tells the rest of the application that something has happened in an aggregate: other slices and modules react to it, and it can never be refused. A name in the past tense makes that visible in every handler and every log: `BookingConfirmed` is a fact, while `ConfirmBooking` reads as a command, a request that a handler may still reject, and `BookingConfirmation` as a document or an entity. Mixing those names lets a reader, or an agent, send a command where an event is expected and the reverse.

The rule cannot know what a name means, which is why it is a suggestion and never an error.

## Diagnostic

```text
HS019: domain event 'ConfirmBooking' is not named as a past fact. Domain events are named in the past tense. Fix: rename it after the fact that happened, with a past participle as its last word. Skill: add-domain-event. Doc: 'docs/rules/HS019.md'.
```

The diagnostic is reported on the name of the type, with the severity `suggestion` (`info` in the compiler log). The fix names no event: the rule does not invent the name of yours. How to fix, below, shows the form.

## Bad example

```csharp
// src/MyApp.Domain/Bookings/Events/ConfirmBooking.cs
public sealed record ConfirmBooking(BookingId BookingId, Guid RoomId) : IDomainEvent;

// src/MyApp.Domain/Bookings/Events/BookingConfirmation.cs
public sealed record BookingConfirmation(BookingId BookingId) : IDomainEvent;
```

## Good example

```csharp
// src/MyApp.Domain/Bookings/Events/BookingConfirmed.cs
public sealed record BookingConfirmed(BookingId BookingId, Guid RoomId, BookingPeriod Period) : IDomainEvent;

public sealed record BookingPaid(BookingId BookingId, decimal Amount) : IDomainEvent;

// A version suffix keeps the fact readable.
public sealed record BookingConfirmedV2(BookingId BookingId, Guid RoomId, BookingPeriod Period, Guid GuestId) : IDomainEvent;
```

## How to fix

1. Name the event after what happened to the aggregate: the aggregate or the subject first, then the verb in the past tense. `ConfirmBooking` becomes `BookingConfirmed`, `BookingConfirmation` becomes `BookingConfirmed`, `PayInvoice` becomes `InvoicePaid`.
2. Rename the type with its file, and the places that raise it or handle it, in the same change.
3. If the verb is irregular and missing from the list above, prefer a verb of the list or ending with `ed` (`BookingAbandoned` rather than `BookingForsaken`): the list is fixed and no exception can be configured.
4. Run the check script again: the suggestion disappears from the IDE and from the compiler log.

## Skill

The message names the `add-domain-event` skill, in `.claude/skills/` and `.agents/skills/`: it generates a domain event, a record named as a past fact, raises it from the aggregate and adds the reaction slice that handles it, so that a module reacts to another without using its types. For an event that already exists, apply the fix above as its steps do, then run the check script.

## Forbidden workarounds

HS019 never blocks the build, but these mechanisms are not valid fixes for HS019 either. Do not use them to silence the suggestion. An exceptional suppression requires an explicit maintainer decision:

- `#pragma warning disable HS019`, `[SuppressMessage]`, `<NoWarn>`, `dotnet_diagnostic.HS019.severity` in `.editorconfig` or `.globalconfig`, or a lower `HardSliceAnalysisMode`.
- Appending a word that ends with `ed` without meaning, such as `ConfirmBookingRequested` for an event that records a confirmation, or a fake version suffix.
- Removing `IDomainEvent` from the event, making it abstract, or changing the contracts of `hardslice.json`.

## What the rule does not detect

- The meaning of the name: a last word that ends with `ed` without being a past participle passes, such as `RoomSeed`, `MediaEmbed` or `BookingNeed`, and so does a past participle that does not describe the fact.
- An irregular past participle missing from the list, such as `BookingForsaken`: it is reported although it is in the past tense.
- Abstract events, event interfaces, and types that carry a fact without implementing `IDomainEvent`.
- A type that is also an entity: HS901 reports it instead.
- Events when `hardslice.json` or its `domainEvent` contract is unusable: HS900 reports the configuration instead.
- Anything outside the `All` analysis mode, and test projects.

# HS014: every command handler and every domain event handler has tests

Severity: error. Reported by the architecture tests (`tests/MyApp.ArchitectureTests/CommandTests.cs`), which fail `dotnet test` and the check scripts.

## Rule

A command changes state: its handler has at least one test at the path of its slice, in `tests/MyApp.Tests/` or `tests/MyApp.IntegrationTests/`. The tests of `src/MyApp/Features/Bookings/ConfirmBooking/` are in `tests/MyApp.Tests/Features/Bookings/ConfirmBooking/` or `tests/MyApp.IntegrationTests/Features/Bookings/ConfirmBooking/`, subfolders included.

A domain event handler, which changes state inside the transaction of a command, follows the same rule: the tests of the reaction slice `src/MyApp/Features/Bookings/NotifyOnBookingConfirmed/` are in `tests/MyApp.IntegrationTests/Features/Bookings/NotifyOnBookingConfirmed/` or its unit test counterpart.

Query handlers are out of this rule. Their slices still have a test folder (HS018).

## How handlers and tests are identified

| Element | Identified by |
|---|---|
| Command handler | a concrete type of the compiled assembly that implements `IRequestHandler<TCommand, TResponse>`, where `TCommand` implements `ICommand<TResponse>` |
| Domain event handler | a concrete type of the compiled assembly that implements `IDomainEventHandler<TEvent>` |
| Its slice | its namespace, `MyApp.Features.<Module>.<Slice>`, which follows its folder. A handler outside any slice needs tests directly in the folder of its namespace |
| A test | a method of a compiled C# file in that folder of a test project, marked `[Fact]`, `[Theory]` or a custom xUnit attribute named like them, such as `[RetryFact]`. Attribute aliases are resolved in their namespace, file and project scope. Commented-out, disabled and compilation-excluded code does not count |

The rule checks that tests exist where an agent or a reviewer looks for them. It does not measure coverage: what the tests prove remains a review matter.

The sources are parsed with each test project's compilation symbols, including framework symbols, project-specific `DefineConstants` and the current Debug/Release configuration. `Directory.Build.targets` supplies those symbols and the evaluated `Compile` files to the architecture project's assembly metadata at build time, without building the test assemblies. A test in an inactive `#if` branch or a file excluded with `Compile Remove` does not count. Files are read from disk at test time: deleted files cannot count through an old assembly.

Aliases such as `using Test = Xunit.FactAttribute;` followed by `[Test]` count too. Global aliases come from the same project's compiled sources, including SDK-generated global usings; namespace and file aliases retain their C# scope and shadowing. Rebuild after changing project inputs or adding sources so the inventory reflects the current project.

## Diagnostic

```text
HS014: command handler 'ArchiveBookingHandler' in slice 'Bookings/ArchiveBooking' has no test in 'tests/MyApp.Tests/Features/Bookings/ArchiveBooking/' or 'tests/MyApp.IntegrationTests/Features/Bookings/ArchiveBooking/'. Every command handler has at least one test at the path of its slice. Fix: add an integration test that sends 'ArchiveBookingCommand', an invalid one included, in 'tests/MyApp.IntegrationTests/Features/Bookings/ArchiveBooking/', and the unit tests of its validator in 'tests/MyApp.Tests/Features/Bookings/ArchiveBooking/'. Skill: add-slice. Doc: 'docs/rules/HS014.md'.
```

A domain event handler without tests is reported the same way:

```text
HS014: domain event handler 'NotifyOnBookingConfirmedHandler' in slice 'Bookings/NotifyOnBookingConfirmed' has no test in 'tests/MyApp.Tests/Features/Bookings/NotifyOnBookingConfirmed/' or 'tests/MyApp.IntegrationTests/Features/Bookings/NotifyOnBookingConfirmed/'. Every domain event handler has at least one test at the path of its slice. Fix: add an integration test in 'tests/MyApp.IntegrationTests/Features/Bookings/NotifyOnBookingConfirmed/' that sends a command whose aggregate raises 'BookingConfirmed' and checks what the handler changed. Skill: add-slice. Doc: 'docs/rules/HS014.md'.
```

The symbol is the handler without tests, followed by the folders searched.

## How to fix

1. Add the integration tests of the command in `tests/MyApp.IntegrationTests/Features/<Module>/<Slice>/<Slice>Tests.cs`, with namespace `MyApp.IntegrationTests.Features.<Module>.<Slice>`. As the tests that `dotnet new hardslice-command` generates do: send the request over HTTP on a real PostgreSQL, check the response and what was persisted, and send an invalid request that is answered with 400.
2. Add the unit tests of its validator in `tests/MyApp.Tests/Features/<Module>/<Slice>/<Slice>ValidatorTests.cs`, one per refused input.
3. For a domain event handler, add the integration tests of its reaction slice, as `dotnet new hardslice-event` generates them: send the command whose aggregate raises the event, over HTTP on a real PostgreSQL, and check what the handler changed, saved with the command.
4. If tests of the handler already exist elsewhere, move them to that folder and update their namespace.

Then run the check script: it must pass with no HS014.

## Skill

The message names the `add-slice` skill, in `.claude/skills/` and `.agents/skills/`: it generates a slice and its tests with `dotnet new hardslice-command` or `hardslice-query`, registers the slice and fills it, which gives it the shape this rule expects. For a slice that already exists, apply the fix above as its steps do, then run the check script.

## Forbidden workarounds

These mechanisms are not valid fixes for HS014. An exception requires an explicit maintainer decision:

- An empty test, a test that asserts nothing, or a test of something else placed in the slice folder only to satisfy the rule.
- A skipped test (`Skip =`), or a test method kept in an inactive `#if` branch or in a comment.
- Turning the command into a query, or implementing `IRequest<T>` directly, while it still changes state.
- Dropping `IDomainEventHandler<TEvent>` from a handler, or calling it some other way, so that the rule no longer recognizes it.
- Deleting, skipping or editing `CommandTests`, `TestSources` or any other code in `tests/MyApp.ArchitectureTests/`.

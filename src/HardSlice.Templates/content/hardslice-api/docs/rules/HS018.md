# HS018: tests mirror the slices

Severity: error. Reported by the architecture tests (`tests/MyApp.ArchitectureTests/TestLayoutTests.cs`), which fail `dotnet test` and the check scripts.

## Rule

The tests of `src/MyApp/Features/<Module>/<Slice>/` are at the same path under `tests/MyApp.Tests/` (unit tests) or `tests/MyApp.IntegrationTests/` (integration tests). An agent or a reviewer who reads a slice finds its tests without searching.

- Every slice, command, query or reaction to a domain event, has a test folder in at least one of the two projects.
- Every module or slice folder under `Features/` of a test project matches a module or slice of `src/MyApp/Features/`: tests never outlive a renamed or deleted slice.

Tests of a module's own code, such as the tests of the mapping `<Aggregate>Configuration`, sit directly in the module folder, `Features/<Module>/`.

## How slices and test folders are identified

| Element | Identified by |
|---|---|
| Slice | a folder `src/MyApp/Features/<Module>/<Slice>/` that holds C# files, and every namespace `MyApp.Features.<Module>.<Slice>` of the compiled assembly |
| Module | a folder `src/MyApp/Features/<Module>/` that holds C# files, and every namespace `MyApp.Features.<Module>` and below |
| Test folder | a folder `Features/<Module>/` or `Features/<Module>/<Slice>/` of `tests/MyApp.Tests/` or `tests/MyApp.IntegrationTests/` that holds C# files, subfolders included |

HS014 also requires a test method in the folder of every command handler's slice.

The symbol is the slice without tests, or the test folder without its slice or module.

## How to fix

1. **A slice has no tests**: add them at its path. For a command, as `dotnet new hardslice-command` generates them: validator tests in `tests/MyApp.Tests/Features/<Module>/<Slice>/` for a command with parameters, integration tests in `tests/MyApp.IntegrationTests/Features/<Module>/<Slice>/`. For a query, as `dotnet new hardslice-query` generates them: integration tests that read through the endpoint. For a reaction slice: integration tests that send the command raising its event and check what its handler changed.
2. **Tests of the slice exist elsewhere**, for example at the root of a test project: move them to the slice folder and update their namespace to match it.
3. **A test folder has no slice**: the slice was renamed, moved or deleted. Move the tests to the folder of the slice they test, or rename the folder as the slice was renamed. Delete them only with the slice they test, when its behavior is removed on purpose.

Then run the check script: it must pass with no HS018.

## Skill

The message names the `add-slice` skill, in `.claude/skills/` and `.agents/skills/`: it generates a slice and its tests with `dotnet new hardslice-command` or `hardslice-query`, registers the slice and fills it, which gives it the shape this rule expects. For a slice that already exists, apply the fix above as its steps do, then run the check script.

## Forbidden workarounds

These mechanisms are not valid fixes for HS018. An exception requires an explicit maintainer decision:

- A placeholder file, an empty test or a test of something else in the slice folder only to satisfy the rule.
- Moving a slice's types out of `Features/<Module>/<Slice>/`, or giving them a namespace that does not match their folder, so that the slice disappears from the rule.
- Deleting tests that still describe existing behavior, instead of moving them to their slice.
- Deleting, skipping or editing `TestLayoutTests`, `TestSources` or any other code in `tests/MyApp.ArchitectureTests/`.

# HS902: every mapped domain entity implements its contract

Severity: error. Reported at build time by `HardSlice.Analyzers`, on the mapping, in the project that contains it. Not reported in test projects.

## Rule

A type of `MyApp.Domain` that EF Core maps as an entity implements `IAggregateRoot` when it is the root of its aggregate, `IEntity` otherwise. HS902 recognizes three mapping forms:

| Mapping | Reported on |
|---|---|
| `class RoomConfiguration : IEntityTypeConfiguration<Room>` | `RoomConfiguration` |
| `public DbSet<Room> Rooms` in a type derived from `DbContext` | `Rooms` |
| `modelBuilder.Entity<Room>()`, with or without its build action | `Entity<Room>` |

Only types declared in the assembly of the `entity` contract of `hardslice.json` are concerned: an EF Core type of the web project, such as an outbox message, is not a domain entity.

## Why

The rules on entities (HS005 to HS008) find them through `IEntity` and `IAggregateRoot` only. An entity without its contract would escape all of them without notice. The EF Core mapping proves the type is an entity, so the build asks for its contract.

## Diagnostic

```text
HS902: 'Room' is mapped as an EF Core entity by 'RoomConfiguration' but implements neither 'IEntity' nor 'IAggregateRoot'. HardSlice classifies domain types only through these contracts. Fix: implement IAggregateRoot if 'Room' is the root of its aggregate, IEntity otherwise, or, if 'Room' is a value object, remove 'RoomConfiguration' or map it with ComplexProperty in its entity. Skill: add-aggregate. Doc: 'docs/rules/HS902.md'.
```

## Bad example

```csharp
// src/MyApp.Domain/Rooms/Room.cs
public sealed class Room
{
    public RoomId Id { get; }
}

// src/MyApp/Features/Rooms/RoomConfiguration.cs
internal sealed class RoomConfiguration : IEntityTypeConfiguration<Room> { /* ... */ }
```

## Good example

```csharp
// src/MyApp.Domain/Rooms/Room.cs: loaded and saved as a whole, the root of its aggregate.
public sealed class Room : IAggregateRoot
{
    public RoomId Id { get; }
}

// A child entity, owned by its aggregate: it has an identity but is reached only through its root.
public sealed class RoomEquipment : IEntity { /* ... */ }
```

## How to fix

1. Decide the role of the type. It is the root of its aggregate when other code loads it by its id, changes it and saves it: implement `IAggregateRoot`. It is a child entity when it has an identity but is reached only through its root: implement `IEntity`.
2. A type with no identity of its own, compared by its values, is a value object: it implements no contract, and is not mapped as an entity. This is also the case of an entity turned into a value object, such as a `record` without `IEntity`, while its old mapping still exists. Remove the mapping the message names: the configuration class, the `DbSet` property or the call to `Entity<T>()`. If the value object is still stored, map it in the configuration of the entity that holds it, with `ComplexProperty` (or `OwnsOne` when it must be stored apart). Never add `IEntity` to a value object to silence HS902. Then add a migration for the changed model.
3. Run the check script again.

## Skill

The message names the `add-aggregate` skill, in `.claude/skills/` and `.agents/skills/`: it generates an aggregate with its identifier, its mapping and its unit tests, and keeps another aggregate by its identifier only. For an aggregate that already exists, apply the fix above as its steps do, then run the check script. The skill does not apply to a value object: follow step 2 of the fix instead.

## Forbidden workarounds

These mechanisms are not valid fixes for HS902. Do not use them to make the build pass:

- `#pragma warning disable HS902`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`, or `dotnet_diagnostic.HS902.severity` in `.editorconfig` or `.globalconfig`.
- Mapping the type in a way HS902 does not recognize (`Entity(typeof(Room))`, by name, or by convention through a navigation) only to escape the rule.
- Mapping an entity with an identity as an owned type only to escape the rule.
- Implementing a homonymous `IEntity` of another namespace or project: only the contract `hardslice.json` names counts.
- Moving the domain type out of `MyApp.Domain`, or editing `hardslice.json`.

## What the rule does not detect

- An entity mapped by convention (discovered through a navigation), by `Entity(typeof(T))` or by its name.
- An owned type (`OwnsOne`, `OwnsMany`) or a complex type (`ComplexProperty`). The mapping does not say whether an owned type is a value object or a child entity, so HS902 does not require a contract from it: only `IEntity` and `IAggregateRoot` decide. A child entity mapped with `OwnsMany` that does not implement `IEntity` therefore escapes HS005 to HS008 without any diagnostic; implement `IEntity` on every child entity.
- An entity that is not persisted and implements no contract.
- A mapping in a project that does not use the HardSlice analyzers.

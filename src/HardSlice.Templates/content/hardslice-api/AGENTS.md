# AGENTS.md

MyApp is an ASP.NET Core API organized in vertical slices around a rich domain. HardSlice enforces this architecture at build time: a violation fails `dotnet build` or `dotnet test`, whoever wrote the code.

## Project map

| Path | Contains |
|---|---|
| `src/MyApp.Domain/` | The contracts that classify domain types: `IEntity`, `IAggregateRoot` (an entity that records its domain events) and `IDomainEvent`. |
| `src/MyApp.Domain/<Module>/` | Aggregates, value objects and business rules. Depends on the base class library only. |
| `src/MyApp.Domain/<Module>/Events/` | Domain events raised by the module aggregates. |
| `src/MyApp/Features/<Module>/<Slice>/` | One use case: its command or query, validator, handler and endpoint. Or one reaction to a domain event: its handler. |
| `src/MyApp/Features/<Module>/` | Module registration (`<Module>Module.cs`, generated by `dotnet new hardslice-module`), EF Core mapping of its aggregates and their child entities (`<Aggregate>Configuration.cs`, `<Entity>Configuration.cs`) and the public contract shared by its slices. |
| `src/MyApp/Shared/` | Cross-cutting code only, never a use case. |
| `src/MyApp/Shared/Messaging/` | The in-house mediator: `IMediator`, `ICommand<T>`, `ISystemCommand<T>`, `IQuery<T>`, `IRequestHandler<,>`, `IPipelineBehavior<,>`, and `IDomainEventHandler<>`. `AddRecurringCommand` sends a system command at regular intervals. |
| `src/MyApp/Shared/Behaviors/` | The pipeline every request goes through, in order: logs, validation, then one transaction per command, which publishes its domain events before it commits. Also the HTTP answers to unreadable requests, such as a date without its offset, and to validation and domain errors. |
| `src/MyApp/Shared/Persistence/` | `AppDbContext`, its registration and the migrations. It declares no module type. |
| `tests/MyApp.Tests/` | Unit tests of the domain, the validators and `Shared`, at the same path as the code they test. |
| `tests/MyApp.IntegrationTests/` | Tests on a real PostgreSQL (Testcontainers), at the same path as the slice they test. `AppFactory` reads no user secret and starts no hosted service of the application: a test of a hosted service keeps it with `new AppFactory(database).KeepHostedService<TService>()`. |
| `tests/MyApp.ArchitectureTests/` | Architecture tests of HS001, HS012 to HS014 and HS016 to HS018, on the compiled assemblies and the test sources. |
| `docs/rules/` | One sheet per HardSlice rule: what it forbids and how to fix it. |
| `hardslice.json` | HardSlice configuration: the `slices` style, the `contracts` that classify entities, events, commands, queries and handlers, and the folders allowed in `Shared`. |
| `.editorconfig` | Severity of the HardSlice analyzer rules. |
| `Directory.Build.props` | Build settings of every project, including `HardSliceAnalysisMode`, set to `All`: every HardSlice analyzer rule is on. |
| `Directory.Build.targets` | Supplies each test project's compilation symbols and compiled source paths to HS014, and the module files of the web project to `dotnet new hardslice-aggregate`, `hardslice-entity`, `hardslice-command`, `hardslice-query` and `hardslice-event`, and its mappings to `hardslice-entity`. |
| `.config/dotnet-tools.json` | Local tools: `dotnet-ef` at the version of EF Core, and `dotnet hardslice` at the version of `HardSlice.Analyzers`. |

## Golden rules

1. For a use case, read its slice and the aggregate it uses, nothing else. A slice is the folder `Features/<Module>/<Slice>/` and its namespace, nothing outside: one request `<Slice>Command` or `<Slice>Query`, `<Slice>Handler`, `<Slice>Validator` if any, and the static class `<Slice>Endpoint` (HS004). A system command, an `ISystemCommand<TResponse>` that only the application sends, such as a job, has no endpoint: a type of its module sends it, `AddRecurringCommand` for a periodic task. A reaction slice holds one domain event handler `<Slice>Handler` and no request nor endpoint.
2. A slice never uses a type from another slice, and its handlers, validator and endpoint stay `internal` (HS016). Share through the domain, a domain event or the module public contract.
3. A module uses another module only through its public contract: the types directly in `MyApp.Features.<Module>` (HS012).
4. Business rules live in the domain aggregates, not in handlers or endpoints: an entity has no public setter, `init` accessor or writable field, and its state changes through its methods (HS007). An aggregate holds another aggregate by its identifier only, `Guid RoomId` and never `Room Room`, from its root and from its child entities (HS008). An endpoint never reaches the database: it sends a command or a query through `IMediator` (HS003). It is mapped in its slice, on the group of its module, and returns `TypedResults` (HS015).
5. A command handler returns an identifier, a DTO of values or nothing: never an entity, not even in a collection, a `Result<T>` or a DTO (HS005). A query handler never writes, never calls `Find` nor `AsTracking`, and starts each query on an entity with `AsNoTracking()` before projecting it to a DTO (HS006).
6. The domain project references nothing but the base class library (HS001). Every aggregate root implements `IAggregateRoot`, every child entity `IEntity` (HS902), and a type has one role (HS901). A domain event is a `record` (HS009) named as a past fact, `OrderShipped` and never `ShipOrder` (HS019, a suggestion).
7. `Shared` holds cross-cutting code only, in the folders `hardslice.json` allows, and never depends on `Features` (HS017).
8. Every behavior change comes with a test at the same path as the code it covers. Every slice has tests at its path under `tests/` (HS018), at least one for a command or domain event handler (HS014), and every command with parameters has a validator (HS013).
9. The domain and the slices never read the system clock (`DateTime.UtcNow`, `DateTimeOffset.UtcNow`...): a handler injects `TimeProvider` and passes the instant to the domain as a parameter (HS010).
10. Asynchronous work is awaited all the way up: never `.Result`, `.Wait()`, `GetAwaiter().GetResult()`, nor `async void`, an async lambda given to an `Action` included (HS011).
11. Never weaken a rule to make the build pass: see [Forbidden](#forbidden).

## Adding a first module

Use the skills `add-module`, then `add-aggregate`, then `add-slice` for each use case. They run, from the root of the solution:

1. `dotnet new hardslice-module --project src/MyApp/MyApp.csproj --name <Module>`, with `--route <route>` for a group other than the module name in kebab-case: the public contract `src/MyApp/Features/<Module>/<Module>Module.cs`, the folder of its domain and its test folders. Add the lines it prints to `Program.cs`.
2. `dotnet new hardslice-aggregate --project src/MyApp/MyApp.csproj --module <Module> --name <Aggregate>`: the aggregate, its `<Aggregate>Id`, its mapping and its unit tests. Rename its factory method `Create` after the business fact, give it its state and its rules, map that state, and add the migration it prints: see [Changing the database](#changing-the-database). Then add its slices as below, and the module to the map above.

## Adding a slice

Use the skill `add-slice`, and `add-domain-event` for a fact other code reacts to. Each template below runs from the root of the solution, refuses a missing module or an existing element (it then prints `created successfully`, fails with exit code 105 and creates nothing), never edits a file, prints the lines to add, and leaves `TODO(hardslice):` markers: the check fails while one is left.

1. Check whether the aggregate already owns the business rule. If not, add it to the aggregate with its unit test.
<!--#if (!NoSample) -->
   A broken rule throws `DomainException`, answered with 400. A rule broken by the current state, such as an overlapping booking, throws a `ConflictException`, answered with 409.
<!--#else -->
   A broken rule throws `DomainException`, answered with 400. A rule broken by the current state, such as a duplicate, throws a `ConflictException`, answered with 409.
<!--#endif -->
2. Generate the slice with its tests: `dotnet new hardslice-command --project src/MyApp/MyApp.csproj --module <Module> --name <Slice>` when it changes state, with `--parameters none` for a command without parameters (an empty record, no validator), `--endpoint none` for a system command (no endpoint, its tests send it through `IMediator`), `--every <interval>` for one sent at regular intervals, `--response none` when it returns only whether its aggregate exists (a `bool`, `false` answered with 404, refused with `--parameters none`) or `--response <Dto>` for a DTO of values (a `Guid` identifier by default); `dotnet new hardslice-query --project src/MyApp/MyApp.csproj --module <Module> --name <Slice> --aggregate <Aggregate>` when it only reads, one DTO by its id or a list with `--result many`. Always pass `--route`, named after the resource rather than the use case (`--route versions`, not `import-schedule`), and `--method PUT`, `PATCH` or `DELETE` for a command that replaces, changes or deletes it (`POST` by default).
<!--#if (!NoSample) -->
   Follow `ConfirmBooking` and `GetBooking`. A slice holds:
<!--#else -->
   A slice holds:
<!--#endif -->
   - a public request: an `ICommand<TResponse>` when it changes state, an `ISystemCommand<TResponse>` when only the application sends it, an `IQuery<TResponse>` when it only reads. The response type is exact (invariant), matching its handler and pipeline;
   - an `internal` validator, an `AbstractValidator<TRequest>`, required for a command with parameters, that checks the shape of the input (required fields, formats, lengths). A failure is answered with 400 naming the fields, before the handler runs. A command without parameters, an empty record, has none: never an empty validator;
   - an `internal` handler that reaches aggregates through `AppDbContext.Set<T>()`. A command handler never calls `SaveChangesAsync`: each command runs in one transaction that the pipeline saves and commits, and any exception rolls it back, detaching tracked entities. Save early only to translate a database error into a domain exception. A command handler may read from outside, such as a download or a file, through services its module registers, such as `IHttpClientFactory` and its options. An effect it has outside survives a rollback, so it must stay harmless then, such as a file named after the hash of its content. An effect that cannot, such as an e-mail or a payment, has no mechanism in this solution yet: tell the user instead of writing it. A query handler reads with `AsNoTracking()`, projects into its public DTO with `Select`, and runs outside any transaction; an unknown id is a `null` response, answered with 404;
   - an `internal` endpoint class, except for a system command, whose `Map(RouteGroupBuilder group)` maps the endpoint on the group of the module. It sends the request through `IMediator` and declares its responses as its return type, built with `TypedResults`, such as `Task<Results<Ok<T>, NotFound>>` (HS015).
   - **Background work** is a system command of the slice it runs. A periodic task is registered with `services.AddRecurringCommand<TCommand, TResponse>(section, interval)` in its module, which `--every` prints: a new command at each interval, in a scope of its own, a failed cycle logged. Any other hosted service lives in the folder of the slice it triggers, sends each command through `IMediator` in a scope of its own, and receives `TimeProvider` (HS010). The skill `add-slice` details both.
3. Register the slice in `<Module>Module.cs` with the lines the template prints. A forgotten registration fails `ProgramTests`, which names the type.
4. Replace every `TODO(hardslice):` marker with the logic and real assertions, an invalid request included for a command with parameters. The tests of a command without parameters cover a failure of the domain, or its success, instead, as `--parameters none` generates them. The tests live at the path of the slice in `tests/MyApp.Tests/Features/<Module>/<Slice>/` and `tests/MyApp.IntegrationTests/Features/<Module>/<Slice>/`: renaming or moving a slice moves them too.

5. A fact other code reacts to is a domain event in `src/MyApp.Domain/<Module>/Events/`, recorded by the aggregate as `Booking.Confirm` records `BookingConfirmed`: `dotnet new hardslice-event --project src/MyApp/MyApp.csproj --module <Module> --name <Event>`, and its reaction slice with `--reaction <Module>/<Reaction>`, or the reaction alone of an existing event with `--reaction-only` too.
<!--#else -->
5. A fact other code reacts to is a domain event in `src/MyApp.Domain/<Module>/Events/`, recorded by the aggregate in its private list and taken by `DequeueDomainEvents()`: `dotnet new hardslice-event --project src/MyApp/MyApp.csproj --module <Module> --name <Event>`, and its reaction slice with `--reaction <Module>/<Reaction>`, or the reaction alone of an existing event with `--reaction-only` too.
<!--#endif -->
   Events are not stored. The pipeline publishes them to their `IDomainEventHandler<TEvent>` after the command handler and before the commit, in the same transaction: an exception of a handler rolls the whole command back. A reaction handler stays `internal`, changes aggregates through `AppDbContext`, never sends a request through `IMediator`, and never has an external effect, such as an e-mail, which would happen even if the transaction rolls back.
6. Add the slice to the map above, then verify.

## Changing the database

1. Map a new aggregate in `src/MyApp/Features/<Module>/<Aggregate>Configuration.cs`, which `dotnet new hardslice-aggregate` generates with the aggregate, and each child entity next to it, in `<Entity>Configuration.cs`, which `dotnet new hardslice-entity --aggregate <Aggregate>` generates, held in a collection of the root or, with `--link id` for a collection too large to load, holding the identifier of its root: an `internal` `IEntityTypeConfiguration<T>` in fluent API. The aggregate implements `IAggregateRoot`, a child entity `IEntity` (HS902). Never add EF Core attributes or references to the domain, and never declare module types in `AppDbContext`.
<!--#if (!NoSample) -->
2. After any mapping change, add a migration. A constraint EF Core cannot model, such as the exclusion constraint that keeps confirmed bookings of a room from overlapping, goes in a migration through `migrationBuilder.Sql`. Never edit a migration that may already be applied.
<!--#else -->
2. After any mapping change, add a migration. A constraint EF Core cannot model, such as an exclusion constraint, goes in a migration through `migrationBuilder.Sql`. Never edit a migration that may already be applied.
<!--#endif -->

   ```text
   dotnet tool restore
   dotnet ef migrations add <Name> --project src/MyApp --output-dir Shared/Persistence/Migrations
   ```

3. The application never migrates its database at startup. Apply migrations with `dotnet ef database update --project src/MyApp`, which reads `ConnectionStrings:Database`. Integration tests apply them to their own container and fail if the model has changes missing from the migrations.

## Running the API

`src/MyApp/appsettings.Development.json` points to a local PostgreSQL. After a first build or check:

```text
docker run --detach --name myapp-postgres --env POSTGRES_PASSWORD=postgres --publish 127.0.0.1:5432:5432 postgres:18-alpine
docker exec myapp-postgres sh -c 'for i in $(seq 60); do pg_isready --quiet --host 127.0.0.1 --username postgres && exit 0; sleep 1; done; echo "PostgreSQL not ready after 60 s" >&2; exit 1'
dotnet tool restore
dotnet ef database update --project src/MyApp
dotnet run --project src/MyApp -- --environment Development --urls http://localhost:5080
```

The second command waits, for at most 60 seconds, until PostgreSQL accepts TCP connections. Override the connection string with the `ConnectionStrings__Database` environment variable. Keep a local secret, such as an API key, out of the repository with `dotnet user-secrets set <Key> <value> --project src/MyApp`: Development reads it, the integration tests never do. Running the API is never a substitute for the check script.

## Verify

```text
bash scripts/check.sh     # macOS, Linux, Git Bash
pwsh scripts/check.ps1    # Windows, PowerShell
```

Both scripts restore the local tools, then run `dotnet hardslice check`: it builds the solution (restoring if needed), then runs the unit tests, the architecture tests and the integration tests. Integration tests need a Docker-compatible container runtime: without one, the check stops before them and says so. Last, it fails while a `TODO(hardslice):` marker is left in `src/` or `tests/`, and lists each one. It exits with code 1 on any failure, its output left as is, and 2 on a wrong argument.

**You are not done until the check script exits 0.** Do not hand back, report success or commit while it fails. If it cannot pass without breaking a rule, stop and explain the conflict instead.

Once a human turns it on in their clone, with `chmod +x .githooks/pre-commit` (macOS, Linux) then `git config core.hooksPath .githooks`, `.githooks/pre-commit` runs `scripts/check.sh` and refuses a commit while it fails: never turn it on yourself, nor skip it with `--no-verify`. CI, `.github/workflows/hardslice.yml`, runs the same check on every push to `main` and every pull request.

## Agent kit

Codex reads this file only. Each other agent also reads its own file, which holds only what is specific to it:

- `.claude/CLAUDE.md` for Claude Code, which imports this file;
- `GEMINI.md` for Gemini CLI, which imports this file;
- `.github/copilot-instructions.md` for GitHub Copilot, which reads this file and `GEMINI.md` too.

Skills, in `.claude/skills/` and their copies in `.agents/skills/`, which every agent reads: `add-module`, `add-aggregate`, `add-slice` and `add-domain-event` generate their element with its template; `extract-to-domain` moves a business rule from the slices into its aggregate; `fix-architecture-violation` fixes a HardSlice failure from the sheet of its rule. Each runs the check.

Hooks: Claude Code (`.claude/settings.json`), Codex (`.codex/hooks.json`) and GitHub Copilot CLI (`.github/hooks/hardslice.json`) run `dotnet hardslice hook`, which refuses the edit of a protected file (see [Forbidden](#forbidden)), builds after each edit of a `.cs` file (budget 10 seconds) and runs the check before the agent hands back (budget 60 seconds), keeping it working while the check fails, three relaunches at most for the same failure and eight in a session. Codex runs them only once a human has approved them in `/hooks`, and skips them silently until then. Gemini CLI has none. Hooks only shorten the loop: the check script decides, so run it before you finish.

## Fixing a HardSlice failure

A HardSlice failure starts with its rule: `HS000`, `HS003` to `HS011`, `HS015`, `HS016` and `HS900` to `HS902` from the analyzers at build time, or `HS001`, `HS012` to `HS014`, `HS016` to `HS018` from the architecture tests. `HS019` is a suggestion of the IDE that never fails the check: follow it when you name an event.

1. Read the diagnostic: it names the offending symbol, the rule, the expected fix, the skill to use after `Skill:` and the sheet after `Doc:`. Use that skill.
2. Open the sheet, or print it with `dotnet hardslice explain <rule>`, and apply the first fix that matches: `docs/rules/HS000.md` (suppressions without justification), `docs/rules/HS001.md` (domain dependencies), `docs/rules/HS003.md` (endpoints), `docs/rules/HS004.md` (shape of a slice), `docs/rules/HS005.md` (command responses), `docs/rules/HS006.md` (query handlers), `docs/rules/HS007.md` (entity state), `docs/rules/HS008.md` (references between aggregates), `docs/rules/HS009.md` (domain events), `docs/rules/HS010.md` (system clock), `docs/rules/HS011.md` (blocking calls and async void), `docs/rules/HS012.md` (modules), `docs/rules/HS013.md` (validators), `docs/rules/HS014.md` (command handler tests), `docs/rules/HS015.md` (slice endpoints), `docs/rules/HS016.md` (slices), `docs/rules/HS017.md` (Shared), `docs/rules/HS018.md` (test folders), `docs/rules/HS019.md` (names of domain events), `docs/rules/HS900.md` (contracts of `hardslice.json`), `docs/rules/HS901.md` (one role per type), `docs/rules/HS902.md` (mapped entities).
3. Run the check script again.

`HS900`, or a message starting with `hardslice.json:`, means the configuration or one of its contracts is missing or invalid: restore them, never adapt them to the code.

## Forbidden

Fix the code, never the rule. Never make a HardSlice diagnostic or an architecture test pass by:

- suppressing it: `#pragma warning disable`, `[SuppressMessage]` (HS000 fails a suppression without justification), `<NoWarn>`, `<WarningsNotAsErrors>`;
- lowering its severity: `dotnet_diagnostic.HS016.severity` in `.editorconfig` or `.globalconfig`, or turning off `TreatWarningsAsErrors`;
- editing `.editorconfig` or `hardslice.json`, for example to allow a new folder in `Shared`;
- turning analyzers off: `<RunAnalyzers>false</RunAnalyzers>`, `<RunAnalyzersDuringBuild>false</RunAnalyzersDuringBuild>` or a `HardSliceAnalysisMode` other than `All`, in a project, in `Directory.Packages.props` or in a `Directory.Build.rsp`;
- removing, editing or downgrading `HardSlice.Analyzers`: its reference in `Directory.HardSlice.props`, the import of that file in `Directory.Packages.props`, a `Remove`, `Update` or `ExcludeAssets` of it in a project or a props file, or the `hardslice.tool` entry of `.config/dotnet-tools.json`;
- deleting, skipping or editing tests in `tests/MyApp.ArchitectureTests/`, or editing `scripts/check.sh` and `scripts/check.ps1`;
- changing `HardSliceGetTestInputs` in `Directory.Build.targets` to hide tests behind different compilation symbols or source paths;
- an empty validator, an empty test or a placeholder file written only to satisfy HS013, HS014 or HS018;
- any other workaround listed in the rule sheets of `docs/rules/`, such as reflection, a public handler or moving a slice's type into the module namespace.

Protected files: `.editorconfig`, `.globalconfig`, `Directory.Build.props`, `Directory.Build.targets` and `Directory.Build.rsp` in any folder; `hardslice.json`, `Directory.HardSlice.props`, `.config/dotnet-tools.json`, `.github/workflows/hardslice.yml`, `Directory.Solution.props`, `Directory.Solution.targets` and `nuget.config` at the root; everything in `scripts/`, `tests/MyApp.ArchitectureTests/`, `.claude/`, `.agents/`, `.codex/`, `.github/hooks/` and `.githooks/`. The hooks refuse any edit of one, its creation included, and CI fails a pull request that changes one without the label `hardslice-approved`, which only a maintainer adds. If the task needs one, stop and explain the conflict. A package of the application needs none: add its version to `Directory.Packages.props`, which the application owns, and its `PackageReference` to the project that uses it.

An exception requires an explicit decision from a maintainer, written next to the suppression as `// hardslice-justification: <reason>` (HS000). Never write one yourself.

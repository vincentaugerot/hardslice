# AGENTS.md

MyApp is an ASP.NET Core API organized in vertical slices around a rich domain. HardSlice enforces this architecture at build time: a violation fails `dotnet build` or `dotnet test`, whoever wrote the code.

## Project map

| Path | Contains |
|---|---|
| `src/MyApp.Domain/` | The contracts that classify domain types: `IEntity`, `IAggregateRoot` (an entity that records its domain events) and `IDomainEvent`. |
| `src/MyApp.Domain/<Module>/` | Aggregates, value objects and business rules. Depends on the base class library only. |
| `src/MyApp.Domain/<Module>/Events/` | Domain events raised by the module aggregates. |
| `src/MyApp/Features/<Module>/<Slice>/` | One use case: its command or query, validator, handler and endpoint. Or one reaction to a domain event: its handler. |
| `src/MyApp/Features/<Module>/` | Module registration (`<Module>Module.cs`, generated by `dotnet new hardslice-module`), EF Core mapping of its aggregates (`<Aggregate>Configuration.cs`) and the public contract shared by its slices. |
| `src/MyApp/Shared/` | Cross-cutting code only, never a use case. |
| `src/MyApp/Shared/Messaging/` | The in-house mediator: `IMediator`, `ICommand<T>`, `IQuery<T>`, `IRequestHandler<,>`, `IPipelineBehavior<,>`, and `IDomainEventHandler<>`. |
| `src/MyApp/Shared/Behaviors/` | The pipeline every request goes through, in order: logs, validation, then one transaction per command, which publishes its domain events before saving. Also the HTTP answers to validation and domain errors. |
| `src/MyApp/Shared/Persistence/` | `AppDbContext`, its registration and the migrations. It declares no module type. |
| `tests/MyApp.Tests/` | Unit tests of the domain, the validators and `Shared`, at the same path as the code they test. |
| `tests/MyApp.IntegrationTests/` | Tests on a real PostgreSQL (Testcontainers), at the same path as the slice they test. |
| `tests/MyApp.ArchitectureTests/` | Architecture tests of HS001, HS012 to HS014 and HS016 to HS018, on the compiled assemblies and the test sources. |
| `docs/rules/` | One sheet per HardSlice rule: what it forbids and how to fix it. |
| `hardslice.json` | HardSlice configuration: the `slices` style, the `contracts` that classify entities, events, commands, queries and handlers, and the folders allowed in `Shared`. |
| `.editorconfig` | Severity of the HardSlice analyzer rules. |
| `Directory.Build.props` | Build settings of every project, including `HardSliceAnalysisMode`, set to `All`: every HardSlice analyzer rule is on. |
| `Directory.Build.targets` | Supplies each test project's compilation symbols and compiled source paths to HS014, and the module files of the web project to `dotnet new hardslice-aggregate`, `hardslice-command`, `hardslice-query` and `hardslice-event`. |
| `.config/dotnet-tools.json` | Local tools: `dotnet-ef` at the version of EF Core, and `dotnet hardslice` at the version of `HardSlice.Analyzers`. |

## Golden rules

1. For a use case, read its slice and the aggregate it uses, nothing else. A slice is the folder `Features/<Module>/<Slice>/` and its namespace, nothing outside: one request `<Slice>Command` or `<Slice>Query`, `<Slice>Handler`, `<Slice>Validator` if any, and the static class `<Slice>Endpoint` (HS004). A reaction slice holds one domain event handler `<Slice>Handler` and no request nor endpoint.
2. A slice never uses a type from another slice, and its handlers, validator and endpoint stay `internal` (HS016). Share through the domain, a domain event or the module public contract.
3. A module uses another module only through its public contract: the types directly in `MyApp.Features.<Module>` (HS012).
4. Business rules live in the domain aggregates, not in handlers or endpoints: an entity has no public setter, `init` accessor or writable field, and its state changes through its methods (HS007). An aggregate holds another aggregate by its identifier only, `Guid RoomId` and never `Room Room`, from its root and from its child entities (HS008). An endpoint never reaches the database: it sends a command or a query through `IMediator` (HS003). It is mapped in its slice, on the group of its module, and returns `TypedResults` (HS015).
5. A command handler returns an identifier, a DTO of values or nothing: never an entity, not even in a collection, a `Result<T>` or a DTO (HS005). A query handler never writes, never calls `Find` nor `AsTracking`, and starts each query on an entity with `AsNoTracking()` before projecting it to a DTO (HS006).
6. The domain project references nothing but the base class library (HS001). Every aggregate root implements `IAggregateRoot`, every child entity `IEntity` (HS902), and a type has one role (HS901). A domain event is a `record` (HS009) named as a past fact, `OrderShipped` and never `ShipOrder` (HS019, a suggestion).
7. `Shared` holds cross-cutting code only, in the folders `hardslice.json` allows, and never depends on `Features` (HS017).
8. Every behavior change comes with a test at the same path as the code it covers. Every slice has tests at its path under `tests/` (HS018), at least one for a command handler (HS014), and every command with parameters has a validator (HS013).
9. The domain and the slices never read the system clock (`DateTime.UtcNow`, `DateTimeOffset.UtcNow`...): a handler injects `TimeProvider` and passes the instant to the domain as a parameter (HS010).
10. Asynchronous work is awaited all the way up: never `.Result`, `.Wait()`, `GetAwaiter().GetResult()`, nor `async void`, an async lambda given to an `Action` included (HS011).
11. Never weaken a rule to make the build pass: see [Forbidden](#forbidden).

## Adding a first module

1. Generate the module from the root of the solution: `dotnet new hardslice-module --project src/MyApp/MyApp.csproj --name <Module>`, with `--route <route>` for a group other than the module name in kebab-case. It creates `src/MyApp/Features/<Module>/<Module>Module.cs`, namespace `MyApp.Features.<Module>`: a public static class whose `Add<Module>Module` registers the slices and `Map<Module>Module` maps them under one `MapGroup`. It also creates the folder of the domain of the module and its test folders, refuses an existing module, never edits a file, and prints the lines that register and map the module in `Program.cs`: add them.
2. Generate the aggregate: `dotnet new hardslice-aggregate --project src/MyApp/MyApp.csproj --module <Module> --name <Aggregate>`. It creates in `src/MyApp.Domain/<Module>/` a `sealed` class implementing `IAggregateRoot` whose state changes only through its methods, with a private list of events that `DequeueDomainEvents()` returns and empties, a static factory method `Create` and a private parameterless constructor for persistence, its `<Aggregate>Id`, its mapping and its unit tests in `tests/MyApp.Tests/Domain/<Module>/`. Rename `Create` after the business fact, give it the state and the rules of the aggregate, map that state, and replace the `TODO(hardslice):` marker.
3. Add the first migration with the command it prints: see [Changing the database](#changing-the-database).
4. Add its slices as below, then add the module to the map above.

## Changing the database

1. Map a new aggregate in `src/MyApp/Features/<Module>/<Aggregate>Configuration.cs`, which `dotnet new hardslice-aggregate` generates with the aggregate: an `internal` `IEntityTypeConfiguration<T>` in fluent API. The aggregate implements `IAggregateRoot` (HS902). Never add EF Core attributes or references to the domain, and never declare module types in `AppDbContext`.
<!--#if (!NoSample) -->
2. After any mapping change, add a migration. A constraint EF Core cannot model, such as the exclusion constraint that keeps confirmed bookings of a room from overlapping, goes in a migration through `migrationBuilder.Sql`. Never edit a migration that may already be applied.

## Running the API

`src/MyApp/appsettings.Development.json` points to a local PostgreSQL. After a first build or check:

```text
docker run --detach --name myapp-postgres --env POSTGRES_PASSWORD=postgres --publish 127.0.0.1:5432:5432 postgres:18-alpine
docker exec myapp-postgres sh -c 'for i in $(seq 60); do pg_isready --quiet --host 127.0.0.1 --username postgres && exit 0; sleep 1; done; echo "PostgreSQL not ready after 60 s" >&2; exit 1'
dotnet tool restore
dotnet ef database update --project src/MyApp
dotnet run --project src/MyApp -- --environment Development --urls http://localhost:5080
```

The second command waits, for at most 60 seconds, until PostgreSQL accepts TCP connections. Override the connection string with the `ConnectionStrings__Database` environment variable. Running the API is never a substitute for the check script.

## Verify

```text
bash scripts/check.sh     # macOS, Linux, Git Bash
pwsh scripts/check.ps1    # Windows, PowerShell
```

Both scripts restore the local tools, then run `dotnet hardslice check`: it builds the solution (restoring if needed), then runs the unit tests, the architecture tests and the integration tests. Integration tests need a Docker-compatible container runtime: without one, the check stops before them and says so. It exits with a non-zero code on any failure, the code of the first step that fails.

**You are not done until the check script exits 0.** Do not hand back, report success or commit while it fails. If it cannot pass without breaking a rule, stop and explain the conflict instead.

## Fixing a HardSlice failure

A HardSlice failure starts with its rule: `HS003` to `HS011`, `HS015`, `HS016` and `HS900` to `HS902` from the analyzers at build time, or `HS001`, `HS012` to `HS014`, `HS016` to `HS018` from the architecture tests. `HS019` is a suggestion of the IDE that never fails the check: follow it when you name an event.

1. Read the diagnostic: it names the offending symbol, the rule, the expected fix and its sheet after `Doc:`.
2. Open the sheet, or print it with `dotnet hardslice explain <rule>`, and apply the first fix that matches: `docs/rules/HS001.md` (domain dependencies), `docs/rules/HS003.md` (endpoints), `docs/rules/HS004.md` (shape of a slice), `docs/rules/HS005.md` (command responses), `docs/rules/HS006.md` (query handlers), `docs/rules/HS007.md` (entity state), `docs/rules/HS008.md` (references between aggregates), `docs/rules/HS009.md` (domain events), `docs/rules/HS010.md` (system clock), `docs/rules/HS011.md` (blocking calls and async void), `docs/rules/HS012.md` (modules), `docs/rules/HS013.md` (validators), `docs/rules/HS014.md` (command handler tests), `docs/rules/HS015.md` (slice endpoints), `docs/rules/HS016.md` (slices), `docs/rules/HS017.md` (Shared), `docs/rules/HS018.md` (test folders), `docs/rules/HS019.md` (names of domain events), `docs/rules/HS900.md` (contracts of `hardslice.json`), `docs/rules/HS901.md` (one role per type), `docs/rules/HS902.md` (mapped entities).
3. Run the check script again.

`HS900`, or a message starting with `hardslice.json:`, means the configuration or one of its contracts is missing or invalid: restore them, never adapt them to the code.

## Forbidden

Fix the code, never the rule. Never make a HardSlice diagnostic or an architecture test pass by:

- suppressing it: `#pragma warning disable`, `[SuppressMessage]`, `<NoWarn>`, `<WarningsNotAsErrors>`;
- lowering its severity: `dotnet_diagnostic.HS016.severity` in `.editorconfig` or `.globalconfig`, or turning off `TreatWarningsAsErrors`;
- editing `.editorconfig` or `hardslice.json`, for example to allow a new folder in `Shared`;
- turning analyzers off: `<RunAnalyzers>false</RunAnalyzers>`, `<RunAnalyzersDuringBuild>false</RunAnalyzersDuringBuild>` or a `HardSliceAnalysisMode` other than `All`;
- removing, editing or downgrading `HardSlice.Analyzers` or its reference in `Directory.Packages.props`, or the `hardslice.tool` entry of `.config/dotnet-tools.json`;
- deleting, skipping or editing tests in `tests/MyApp.ArchitectureTests/`, or editing `scripts/check.sh` and `scripts/check.ps1`;
- changing `HardSliceGetTestInputs` in `Directory.Build.targets` to hide tests behind different compilation symbols or source paths;
- an empty validator, an empty test or a placeholder file written only to satisfy HS013, HS014 or HS018;
- any other workaround listed in the rule sheets of `docs/rules/`, such as reflection, a public handler or moving a slice's type into the module namespace.

An exception requires an explicit decision from a maintainer.

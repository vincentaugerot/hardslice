# HardSlice.Analyzers

Roslyn analyzers that keep a [HardSlice](https://github.com/vincentaugerot/hardslice) solution in vertical slices around a rich domain. A violation fails `dotnet build` with a one-line diagnostic that names the offending symbol, the expected fix and the sheet of the rule: an AI coding agent reads it and repairs the architecture instead of working around it.

This is a preview. The package is meant for the solutions generated by the `hardslice-api` template of [HardSlice.Templates](https://www.nuget.org/packages/HardSlice.Templates), which references it from `Directory.Packages.props` at the version of the `HardSlice.Tool` local tool, and carries the sheets its diagnostics point to in `docs/rules/`.

## What it reports

- HS000, not configurable: a suppression of a HardSlice rule in source, `#pragma warning disable` or `[SuppressMessage]`, without a `// hardslice-justification:` comment on its line or the line above
- HS003 to HS011, HS015 and HS016: endpoints that reach the database, the shape of a slice, command handlers that return an entity, query handlers that track or write, entity state writable from outside, aggregates that hold another aggregate, domain events that are not records, reads of the system clock, blocking calls and `async void`, endpoints mapped outside their slice, references between slices
- HS019, a suggestion: domain events not named as past facts
- HS900 to HS902: a `hardslice.json` without `"version": 1` or with contracts that are unusable or ambiguous, and mapped entities without their contract.

The MSBuild property `HardSliceAnalysisMode` turns the rules on: `Minimum`, `Recommended` (when it is not set) or `All`. A `dotnet_diagnostic.<rule>.severity` line of `.editorconfig` takes precedence over the mode, except for HS000, which no mode, `.editorconfig` line or `<NoWarn>` turns off.

The package is a development dependency: it adds nothing to the runtime of the application.

# HardSlice.Tool

The `dotnet hardslice` command of [HardSlice](https://github.com/vincentaugerot/hardslice): verifies a solution generated by the `hardslice-api` template of [HardSlice.Templates](https://www.nuget.org/packages/HardSlice.Templates) and explains its rules.

This is a preview. It is a local tool: every generated solution pins it in `.config/dotnet-tools.json` at the version of [HardSlice.Analyzers](https://www.nuget.org/packages/HardSlice.Analyzers), without roll forward. Restore it in the solution:

```text
dotnet tool restore
dotnet hardslice check
dotnet hardslice explain HS016
dotnet hardslice upgrade
```

- `check` builds the solution, then runs its unit, architecture and integration tests, then fails while a `TODO(hardslice):` marker is left in `src/` or `tests/`, listing each file and line. It exits with `0` when the check passes, `1` when a step fails, whatever the code of the step, its output left as is, and `2` on a wrong command line only, as `check --build`. It stops before the build when `Directory.HardSlice.props` references another version of `HardSlice.Analyzers` than its own, when `Directory.Packages.props` no longer imports it, or when one of the three test projects is no longer in the `.slnx` (its tests would run on old binaries). Each error on a HardSlice file that is missing or holds another version gives its probable cause, a solution generated by another template or another version of the tool, a `Fix:`, which names `upgrade`, and a `Doc:` to the section of the getting started guide that describes these files. After the build, it fails when a project of the `.slnx` did not receive `HardSlice.Analyzers` at its restore. It has no option to skip a step: it is the only verdict on the work.
- `check --build` is the verification after an edit, for the hooks of the agents: the incremental build with `--no-restore`, after a restore only when a project has never been restored or a file its restore reads changed since its last restore, printing the errors alone as the compiler wrote them, then the `TODO(hardslice):` markers. It runs no test and says that only `check` decides. Any other argument exits with code 2.
- `hook <cli> <event>` runs the hooks of the agents that the solution declares: `hook claude PreToolUse|PostToolUse|Stop` for Claude Code (`.claude/settings.json`), `hook codex PreToolUse|PostToolUse|Stop` for Codex (`.codex/hooks.json`) and `hook copilot preToolUse|postToolUse|agentStop` for Copilot CLI (`.github/hooks/hardslice.json`). From the payload of the CLI on the standard input, it refuses the edit of a protected file, runs `check --build` after the edit of a `.cs` file (every file of a Codex patch), handing the errors of the edited files in full and only the count of the others, unless no error is in an edited file, and `check` before the agent hands back, at most three relaunches for the same failure and eight in a session. When `check` stops before the build on `.config/dotnet-tools.json` or `Directory.HardSlice.props`, protected files that only a maintainer can fix, the hook hands the error to the agent once in the session, then lets it hand back and tell the user what a maintainer must do. A hook that fails never lets the agent through: before an edit, it refuses the edit with the error, after it the agent reads a failed verification, and before it hands back it keeps the agent working once. Its payload and answers are read and written in UTF-8, and it starts the `dotnet` of `DOTNET_HOST_PATH` when that is set. It answers with code 2 and the standard error for Claude Code and Codex, and in JSON on the standard output with code 0 for Copilot CLI (`permissionDecision`, `additionalContext`, `decision: "block"`). The hooks of Claude Code exit 0 at once under Copilot CLI (`COPILOT_CLI`), which runs them too. An unknown CLI or event, or a payload that is not JSON, exits with code 1.
- `protected` reads paths relative to the root of the solution on the standard input, separated by NUL characters (`git diff --name-only -z`, recommended) or one per line, and lists those that agents never edit, the list of the hooks: it exits with code 1 when one is protected, 0 when none is, and 2 outside a generated solution, with an argument, or on a line that git quoted (a name with a character other than printable ASCII, which only `-z` keeps as is). The CI of the solution, `.github/workflows/hardslice.yml`, runs it on the files of a pull request: `git diff --name-only --no-renames -z HEAD^1 HEAD | dotnet hardslice protected`.
- `upgrade` brings the solution to the template of the version of the tool, from a git tree without changes but `.config/dotnet-tools.json`, which the update of the tool changes. It generates `hardslice-api` again under the name of the solution, in a temporary folder and a template hive of its own, from the package sources of the `nuget.config` files of the solution, without the sample when the solution has neither `src/<App>/Features/Bookings/` nor `src/<App>.Domain/Bookings/`, unless `--sample` or `--no-sample` says otherwise. It rewrites the files that the template owns, the protected files and the rule sheets, adds the files that the solution lacks, and lists the files of the application that differ from the new generation with their diff, to merge by hand or with the agent, the files of the solution that the template may have moved (a file with the name of an added file in another folder), and the files of the folders of the template that it no longer generates. It exits with code 0 when nothing is left to merge, 3 when files are listed to merge or to review, 1 when it fails, before writing anything unless it says otherwise, and 2 on a wrong command line. It writes protected files: a maintainer runs it, never an agent.
- `explain <rule>` prints the sheet of a rule. An unknown rule exits with code 2 and lists the rules that have a sheet.
- `--help` or `-h` prints the usage. After a command, alone (`dotnet hardslice upgrade --help`), it prints the help of that command, its paragraph of the usage with its exit codes, and exits with code 0 without running it. Mixed with other arguments of the command, it is a wrong command line.
- `--version` prints the version of the tool.

# HardSlice.Tool

The `dotnet hardslice` command of [HardSlice](https://github.com/vincentaugerot/hardslice): verifies a solution generated by the `hardslice-api` template of [HardSlice.Templates](https://www.nuget.org/packages/HardSlice.Templates) and explains its rules.

This is a preview. It is a local tool: every generated solution pins it in `.config/dotnet-tools.json` at the version of [HardSlice.Analyzers](https://www.nuget.org/packages/HardSlice.Analyzers), without roll forward. Restore it in the solution:

```text
dotnet tool restore
dotnet hardslice check
dotnet hardslice explain HS016
```

- `check` builds the solution, then runs its unit, architecture and integration tests, then fails while a `TODO(hardslice):` marker is left in `src/` or `tests/`, listing each file and line. It exits with `0` when the check passes, `1` when a step fails, whatever the code of the step, its output left as is, and `2` on a wrong command line only, as `check --build`. It stops before the build when `Directory.HardSlice.props` references another version of `HardSlice.Analyzers` than its own, when `Directory.Packages.props` no longer imports it, or when one of the three test projects is no longer in the `.slnx` (its tests would run on old binaries). Each error on a HardSlice file that is missing or holds another version gives its probable cause, a solution generated by another template or another version of the tool, a `Fix:` and a `Doc:` to the section of the getting started guide that describes these files. After the build, it fails when a project of the `.slnx` did not receive `HardSlice.Analyzers` at its restore. It has no option to skip a step: it is the only verdict on the work.
- `check --build` is the verification after an edit, for the hooks of the agents: the incremental build with `--no-restore`, after a restore only when a project has never been restored or a file its restore reads changed since its last restore, printing the errors alone as the compiler wrote them, then the `TODO(hardslice):` markers. It runs no test and says that only `check` decides. Any other argument exits with code 2.
- `hook <cli> <event>` runs the hooks of the agents that the solution declares: `hook claude PreToolUse|PostToolUse|Stop` for Claude Code (`.claude/settings.json`), `hook codex PreToolUse|PostToolUse|Stop` for Codex (`.codex/hooks.json`) and `hook copilot preToolUse|postToolUse|agentStop` for Copilot CLI (`.github/hooks/hardslice.json`). From the payload of the CLI on the standard input, it refuses the edit of a protected file, runs `check --build` after the edit of a `.cs` file (every file of a Codex patch) and `check` before the agent hands back, at most three relaunches for the same failure and eight in a session. A hook that fails never lets the agent through: before an edit, it refuses the edit with the error, after it the agent reads a failed verification, and before it hands back it keeps the agent working once. Its payload and answers are read and written in UTF-8, and it starts the `dotnet` of `DOTNET_HOST_PATH` when that is set. It answers with code 2 and the standard error for Claude Code and Codex, and in JSON on the standard output with code 0 for Copilot CLI (`permissionDecision`, `additionalContext`, `decision: "block"`). The hooks of Claude Code exit 0 at once under Copilot CLI (`COPILOT_CLI`), which runs them too. An unknown CLI or event, or a payload that is not JSON, exits with code 1.
- `protected` reads paths relative to the root of the solution on the standard input, separated by NUL characters (`git diff --name-only -z`, recommended) or one per line, and lists those that agents never edit, the list of the hooks: it exits with code 1 when one is protected, 0 when none is, and 2 outside a generated solution, with an argument, or on a line that git quoted (a name with a character other than printable ASCII, which only `-z` keeps as is). The CI of the solution, `.github/workflows/hardslice.yml`, runs it on the files of a pull request: `git diff --name-only --no-renames -z HEAD^1 HEAD | dotnet hardslice protected`.
- `explain <rule>` prints the sheet of a rule. An unknown rule exits with code 2 and lists the rules that have a sheet.
- `--version` prints the version of the tool.

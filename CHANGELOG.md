# Changelog

Every version of the three packages, `HardSlice.Templates`, `HardSlice.Analyzers` and `HardSlice.Tool`, which always share one version. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). While HardSlice is in preview, a version may change its rules, its template and its commands, but a solution keeps the template and the versions it was generated with.

## [0.3.0-preview.1] - unreleased

The first preview published on NuGet.org. No earlier version was published.

### Added

- `hardslice-api`, a solution template: an ASP.NET Core API in vertical slices around a separate domain project, with PostgreSQL and EF Core, a small in-house mediator, FluentValidation, unit, integration and architecture tests, and a `Bookings` sample module, or none with `--no-sample`. Any name accepted by `dotnet new` becomes one safe .NET namespace (`my-app` becomes `my_app`).
- Six item templates, `hardslice-module`, `hardslice-aggregate`, `hardslice-entity`, `hardslice-command`, `hardslice-query` and `hardslice-event`, which generate an element in its place with its tests and print the registrations to add. Their tests fail with a `TODO(hardslice):` marker until the element is completed.
- `HardSlice.Analyzers`, 16 rules reported at build time and in the IDE: HS000 (suppressions without justification), HS003 to HS011, HS015, HS016, HS019 (a suggestion) and the configuration diagnostics HS900 to HS902. Three analysis modes, `Minimum`, `Recommended` and `All`, choose which rules are on.
- Seven architecture tests in every generated solution: HS001, HS012 to HS014 and HS016 to HS018.
- `HardSlice.Tool`, the local tool `dotnet hardslice`, pinned to the version of the analyzers: `check` (exit codes `0`, `1` and `2`), `check --build`, `explain <rule>`, `hook <cli> <event>` and `protected`.
- The agent kit of every generated solution: `AGENTS.md` and the instruction files of Claude Code, Codex, GitHub Copilot CLI and Gemini CLI, six skills, the hooks of Claude Code, Codex and Copilot CLI (they refuse an edit of a protected file, hand the build errors back after an edit and keep the agent working while the check fails), a pre-commit hook, and a GitHub Actions workflow that runs the check and fails a pull request that changes a protected file without the label `hardslice-approved`.
- A rule sheet for every rule in `docs/rules/`, named by each diagnostic with the skill that fixes it.
- `hardslice.json` declares `"version": 1`, the version of its format.
- The application owns `Directory.Packages.props` and adds its packages there. `HardSlice.Analyzers` is referenced from the protected `Directory.HardSlice.props`, which it imports, and `check` fails when a project no longer receives the package. The test projects reference `Microsoft.Extensions.TimeProvider.Testing`, for `FakeTimeProvider`.
- `check --build`, which the hooks run after each edit, restores before the build only when a project has never been restored or the content of a file its restore reads changed since its last successful restore, so that an edit of a `.cs` file never waits for a restore.
- The web project has its own `UserSecretsId`, so `dotnet user-secrets set` needs no init. `AppFactory` runs the integration tests in the `IntegrationTests` environment, which reads no user secret, and starts no hosted service of the application unless the test keeps it with `KeepHostedService<T>()`.
- The agent kit says that a command without parameters has no validator and tests a failure of the domain, or its success, instead of an invalid request, and the fix of HS014 says so for such a command. It says that a command handler may read from outside through the services of its module, such as `IHttpClientFactory`, and that an effect it has outside must stay harmless if its transaction rolls back.
- `hardslice-command --parameters none` generates a command without parameters: an empty record, an endpoint that reads no body, no validator nor validator tests, and an integration test of its success instead of a 400. It refuses `--response none`, whose 404 answers an aggregate that such a command cannot name.
- `hardslice-command` and `hardslice-query` take `--route`, the route of the endpoint under the group of its module (route parameters included, `/` for the group itself), and `--method`: `POST`, `PUT`, `PATCH` or `DELETE` for a command, whose `DELETE` reads its `Id` from the route, `GET` for a query. The contract of a module holds the route of its group in its constant `Route`, under which the generated tests call their slice.
- `hardslice-entity` generates a child entity of an aggregate: the entity, its identifier, its mapping next to the mapping of its root and its unit tests, with the converter of the identifier of the root, created with the first child and reused by the next ones. `--link collection`, by default, holds the child in a collection of the root, loaded and saved with it. `--link id` gives the child the identifier of its root instead, without navigation, for a collection too large to load with its root.
- A system command, `ISystemCommand<TResponse>`, which derives from `ICommand<TResponse>`, for a command that only the application sends, such as a job: it goes through the pipeline of every command, and HS004 requires no endpoint for it but refuses one, an HTTP mapping that sends it, and a system command that no type of its module sends. Its contract is the optional key `systemCommand` of `hardslice.json`, which the template writes, and HS900 reports one that does not derive from `command`. `hardslice-command --endpoint none` generates it, without endpoint, with integration tests that send it through `IMediator`, and refuses `--route` and `--method` with it.
- `services.AddRecurringCommand<TCommand, TResponse>(section, interval)`, in `Shared/Messaging`, sends a system command without parameter at regular intervals, one cycle at a time, each in a scope of its own, on the `TimeProvider` of the container: a failed cycle is logged and the next one runs. The key `<section>:Interval` of the configuration replaces the interval. `hardslice-command --every <interval>` generates such a command and prints its registration, with an integration test that runs three cycles through `RecurringCommandCycles` on a `FakeTimeProvider`. `AGENTS.md` and `add-slice` say where background work goes.
- HS010 reports `Task.Delay` and `new PeriodicTimer` without a `TimeProvider` in a slice.
- `TransactionBehavior` answers a unique violation of PostgreSQL with 409, as a `ConflictException` whose message never repeats the values of the key, so that two commands that create the same aggregate under a unique key at the same time answer 201 and 409, never 500. A handler that translates the violation into an exception of its domain keeps it. `AGENTS.md` and `add-slice` say that such a command relies on its unique index, and when a handler takes a transaction lock instead.
- `hardslice-query --result filtered --parameter <Name>:<Type>` generates a query of the list that a filter selects, such as `--parameter Date:DateOnly`: the filter is read from the query string, checked by a validator with its unit tests, and a request without it is answered with 400, which an integration test asserts. The type of the filter is one of `string`, `bool`, `int`, `long`, `decimal`, `double`, `Guid`, `DateOnly`, `TimeOnly` and `DateTimeOffset`. The DTO of every query is named after the slice without its verb: `GetBooking` returns `BookingDto`.
- HS006 follows a rule of the domain that a query runs in the database, a method from `IQueryable<T>` to `IQueryable<TResult>` that receives the queries of the handler: it reports the composed query when its result holds an entity and a query passed to it has no `AsNoTracking()`. The sheet of HS006 and `extract-to-domain` say which forms such a rule takes, a predicate `Expression<Func<T, bool>>` or such a composition, and which helper is a forbidden workaround.
- The agent kit says when a command writes the children of a root in bulk, outside the change tracker: it saves the root early, then writes the children through the connection of `AppDbContext`, in the transaction of the command, under immediate foreign keys and with a longer timeout for that command only (`add-aggregate`, "Children written in bulk"). No bulk helper is generated.
- `hardslice-module` creates the contract of the module alone: the templates of its aggregates, entities, slices and events create the folder of its domain and its test folders, so no `.gitkeep` is left next to their files.
- The fix of HS902 also covers a type that became a value object while still mapped as an entity: remove the mapping that the message names (the configuration, the `DbSet` or the call to `Entity<T>()`), or map the type with `ComplexProperty` in its entity, as its sheet details.
- Every error of `dotnet hardslice check` on a HardSlice file that is missing or holds another version (`Directory.HardSlice.props`, `Directory.Packages.props`, `.config/dotnet-tools.json`) gives its probable cause, a solution generated by another template or another version of the tool, a `Fix:` (a maintainer copies the file from the same template generated anew with `dotnet new hardslice-api -n <Name> --no-sample` in a temporary folder, or sets the tool back to the version of the solution) and a `Doc:` to the section of `getting-started.md` that describes these files.
- After an edit, the hook hands the agent the errors of the edited files in full and only counts the others (`12 more errors in 4 other files`), which the next edits of a change may fix. When no error is in an edited file, every error comes in full, and the check at the end of a turn still lists them all.
- When the check stops before the build on a protected HardSlice file, `.config/dotnet-tools.json` or a `Directory.HardSlice.props` that is missing or holds another version, the hook at the end of a turn hands the error to the agent once in the session, then lets it hand back and tell the user what a maintainer must do, instead of relaunching it three times on a failure it cannot fix. A failure of the build, the tests or the markers keeps its relaunches.
- `Shared` has a fourth default folder, `Http`, for the HTTP pipeline: the answers to unreadable requests and to validation and domain errors (`BadRequestExceptionHandler`, `ValidationExceptionHandler`, `DomainExceptionHandler`, `ExplicitOffsetJsonConverter`) moved there from `Behaviors`, which keeps the mediator pipeline only, with the same answers. `hardslice.json` allows `Messaging`, `Persistence`, `Behaviors` and `Http`, its format unchanged, and the sheet of HS017 and `AGENTS.md` say that an authentication scheme, the authorization policies, rate limiting and CORS go in `Http`. The sheet of HS015 says that a response of the middleware, such as the 401 of a policy, is not in the signature of the endpoint, that a policy goes on the group of the module when it covers all its endpoints and on the endpoint in its slice otherwise, that a `FallbackPolicy` protects every endpoint without `AllowAnonymous`, and that an integration test of the 401 covers it.
- The `add-aggregate` skill says how to change the shape of a table that already holds rows, which `dotnet ef migrations add` scaffolds as drops and adds that lose them: read the migration before applying it, rewrite the loss as a conversion in SQL with a `Down` that converts back, apply a long conversion with a longer command timeout for that run only (`dotnet ef database update --connection`), and try it both ways on a copy of the data. It also says how to map private fields (`Property<T>("_field")`, `PrimitiveCollection<T[]>("_field")`) behind the read-only view that HS007 expects, when an entity stores its state in another shape than the one it shows. `AGENTS.md` sends there from "Changing the database".
- `hardslice-command` and `hardslice-query` take `--require <policy>`, which protects the endpoint with an authorization policy of the application: the endpoint chains `.RequireAuthorization("<policy>")`, an integration test asserts its 401 without authentication, next to the test of the 400, and the other generated tests send their requests through `app.CreateAuthorizedClient("<policy>")`. `AppFactory` holds the client of each policy in `AuthorizedClients`, which the application fills once, and fails a test that asks for a policy without client with a message that says where to add it. `--require` is refused with `--endpoint none`, `--every` and `--daily-at`. The `add-slice` skill says how to protect an endpoint: the scheme and its policies in `Shared/Http`, the policy on the group or on the endpoint, `--require` and the client of the tests.
- `AddRecurringCommand` also takes a `RecurringSchedule`: `RecurringSchedule.DailyAt(time, timeZone)` sends the command every day at a local time of an IANA time zone, a time that a change of the clocks skips moving forward by the length of the change and a repeated one sent once, and `WithRetries(delay, count)` sends it again after a failed cycle, at a fixed interval or every day, then waits for the next instant after the last retry. The keys `DailyAt`, `TimeZone`, `RetryDelay` and `Retries` of its section replace them, as `Interval` does. It schedules any command without parameter, a command that its endpoint also sends included. `hardslice-command --daily-at <hh:mm> --time-zone <id>` generates a daily system command, and `--retry <delay>x<count>` its retries, with `--every` too, with integration tests that run two days of cycles and fail a cycle and each retry. `RecurringCommandCycles` moves the clock to the instant that the service waits for, whatever the schedule, gives it with `NextDueAsync`, fails cycles with `FailNext`, and configures the instance that runs the cycles with an optional `Action<IWebHostBuilder>`.
- A recurring command can have conditions: an `IRecurringCommandCondition<TCommand>` in the folder of its slice, registered by its module, which `ProgramTests` checks, reads its options or the database without tracking before each send, in a scope of its own, and returns the reason the command is not sent, such as a key that is not set. It receives the `RecurringCycle` it decides on: its instant, its retry, and whether it is the cycle at start. The cycle then sends nothing and is not retried, and the reason is logged once until it changes, instead of an error at each cycle. `RecurringSchedule.AlsoAtStart()`, or the key `AtStart` of its section, also sends the command once at start, under the same conditions. `RecurringCommandCycles.RunNextAsync` throws `HeldCycleException` for a cycle held back. `AppFactory` logs each hosted service of the application that it removes, with the call that keeps it. `AGENTS.md` and `add-slice` say that a job decides whether to run through a condition, which also checks the settings it needs, rather than a hosted service or `ValidateOnStart`.

### Known limitations

- Only solutions generated by `hardslice-api` are supported. Adoption of an existing solution is planned for v0.5.
- PostgreSQL is the only database. Domain events are handled inside the transaction of the command, without outbox: an external effect that a rollback must cancel, such as an e-mail, has no mechanism yet, and the agent kit asks the agent to tell the user instead of writing it.
- Gemini CLI stays at the fallback level, without hooks. Codex runs the hooks only once a human approves them in `/hooks`.
- The limits of each rule are listed in [docs/rules.md](docs/rules.md).
